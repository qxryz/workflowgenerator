# 建筑空间飞行

## 1. 技能目标

把用户的一句话建筑/城市视频需求，转换成一套“真实资料约束 + 可编辑 Blender 场景 + 可控电影级 FPV 镜头 + 生成式视觉渲染”的完整生产流程。

最终核心交付：

- `project.blend`：可编辑 Blender 工程，保留场景、几何、命名、摄影机路径、动画、基础灯光和必要参考。
- `previs.mp4`：Blender 原生渲染的 2560 × 1440、16:9 RGB 预演视频，用户确认后锁定。
- `style_anchor_01..04`：3–4 张经 GPT Image 生成/转换的关键状态风格图。
- `final.mp4`：由 H3 根据 Blender RGB 视频、已确认的一致风格关键帧和 Astra 模块化 Prompt 生成的视频。
- `visual_bible.json`、`style_consistency_qa.json`、`h3_prompt.txt`：视觉规范、整组 QA 记录和实际提交提示词。
- `reference_manifest.json`、`model_qa.json`：参考来源、事实/推演区分、图片与模型部件对应关系及几何检查。
- `shot_manifest.json`：记录时长、FPS、镜头路线、关键时间点、焦距、速度档位和确认状态。

默认使用中文与用户沟通；工具内部可以使用英文参数、代码和提示词。

---

## 2. 核心定位

CineFlight 3D 不是“单纯 Blender 建模 Skill”，也不是“单纯 AI 视频生成 Skill”。

它将三类能力分工：

### Astra / Codex：导演与流程编排
负责：

- 理解用户目标；
- 搜集/整理真实参考；
- 规划空间结构；
- 决定建模精度；
- 规划 FPV 镜头；
- 控制 Blender；
- 选择关键状态帧；
- 生成 GPT Image 风格提示；
- 生成 H3 最终提示词；
- 组织用户确认节点；
- 根据失败类型定位回滚阶段。

### Blender：准确空间与摄影机母版
负责：

- 几何轮廓；
- 主体比例；
- 标志性结构；
- 场景布局；
- 内外空间连接；
- 摄影机路径；
- 一镜到底运动；
- 基础动画；
- 预演；
- 可选光影参考。

### GPT Image + H3：最终视觉
GPT Image 负责统一视觉世界与跨状态风格传播；H3 以 Blender RGB 视频作为唯一视频输入，结合已确认风格关键帧重新生成完整视频。

一句话原则：

> Blender 把世界搭对、把镜头拍对；Visual Bible 与 GPT Image 把整组关键帧统一；H3 按 RGB 视频的空间运动生成最终风格。

---

## 3. 适用范围

优先支持：

- 单栋建筑；
- 真实地标；
- 建筑群；
- 城市天际线；
- 街景；
- 街区；
- 室外到室内的建筑飞行；
- 未来城市、赛博城市、线稿城市等风格化建筑环境；
- 以硬表面、直线、体块和明确空间结构为主的场景。

不把以下内容作为第一优先能力：

- 复杂人物表演；
- 动物主体；
- 高密度群演调度；
- 软体角色动画；
- 对角色表情、肢体细节有高要求的剧情镜头。

如用户明确要求，可作为环境中的次要元素处理，但不得牺牲建筑空间和镜头稳定性。

## 4. 默认输出规则

- 时长：10–15 秒；根据主体复杂度、镜头路线和 FPV 强度自动决定；不得超过 15 秒。
- Blender 视频预演：2560 × 1440、16:9、100% 渲染比例、方形像素；完整动画逐帧原生渲染，不得低分辨率放大冒充。内部静态试渲染可降尺寸，提交确认 A 的视频不可降级。
- 默认：一镜到底。
- 只有用户明确要求切镜时才设计多镜头。
- 默认风格：写实现实电影光影。
- 默认镜头强度：`Dynamic FPV`。
- 风格图固定 3–4 张：视频第 0 秒与结束时刻对应的两个状态必须风格化，再加中间 1–2 个关键状态。全部作为全能参考图片。
- H3 默认只生成 1 次；生成后交给用户评估，不做无限自动重试。
- 需要用户确认两个阶段：
  1. Blender 模型 + 运镜预演；
  2. 自动一致性 QA 通过后的全部 3–4 张最终关键帧（一次性确认 B）。
- Master Style Frame 为内部制作步骤，不另设用户确认。

## 5. 详细规则按需读取

### 5.1 建模与真实资料
**首先执行参考研究，禁止收到建筑名称就凭印象直接搭模型。** 开始搜索前读取 [references/modeling.md](references/modeling.md) 中“主动搜图与建模准入”和“内置参考图提示词”。这些规则与提示词已内置，不依赖运行时访问外部 Skill。

1. 主动根据用户要求搜索网上图片并实际打开查看：主体名称/所在地/别名，加正面、侧面、屋顶、入口等相关视角；按计划经过的空间补充图片。用户图优先，网络参考用于补足。
2. 保存可用图片或可再次访问的视觉资源，记录来源、已查看证据、结构观察及缺口到 `reference_manifest.json`。只搜索文字、只读图片标题、列出链接或下载后未查看都不算研究完成。
3. 按镜头需要判断资料是否足够。身份、主要比例、标志构件或经过区域缺少可靠依据时，先列明缺口并询问用户是否生成建模参考图；未同意前不得调用生图补设定，也不得直接猜造缺失结构。
4. 用户同意后，使用 modeling.md 内置的外观设定/对齐视图/空间与局部提示词，仅补所需内容；标记生成图与推演部分，再检查图间一致性。用户不同意则等待其补图或选择缩小路线范围，不擅自降级。
5. 参考准入通过后，将图片里的特征映射到 Blender 部件，先内部草模，再完善和对照实际几何。模型质量检查通过后才提交确认 A；不能用抽象体块草模冒充已完成的建筑预演。

资料不足询问是有条件的方向选择，不增加每次必经的用户确认点；常规流程仍为 A/B。用户已经授权同一范围的参考图生成时沿用授权。

真实地标主动研究多视角、屋顶/鸟瞰、结构/平面、标志局部、入口、内部及 Camera 经过区域；用户图优先，明显冲突时指出并让用户决定。采用“分层精准”：Blender 精准保证身份、轮廓、比例、标志构件、主要开口、空间布局、室内外连接和 Camera 经过区域；微小装饰、远景重复件、微观材质可简化。离 Camera 越近、停留越久，几何越精细。

**建模或修改 Blender 前必须读取 [references/modeling.md](references/modeling.md)。** 其中保留真实参考重建、比例坐标、BlenderMCP/Bridge、保存安全、Collection、先大形后细节、镜头空间建模、重复模块、可编辑性、同模型正/侧/俯视校准和已有成果复用规则。

可按需运行 `scripts/prepare_scene.py` 初始化标准 Collection、Camera Rig、24fps/10–15秒时间线；不得覆盖用户已确认资产。

### 5.2 FPV、预演与 Cycles
默认电影级 FPV、一镜到底。三档：`Smooth Cinematic`、`Dynamic FPV`（默认）、`Extreme FPV`。简单建筑约10–11s，中等11–13s，复杂地标/外到内13–15s，城市13–15s。

建筑镜头语法：全貌→接近→外立面弧线/环绕→标志结构 Reveal→升降/侧绕→有动机入口→连续进入→内部 Reveal→Hero Landing。城市：高位建立→下降入城→建筑峡谷/街道加速→前景视差→狭窄节点→转向/贴立面→拉升冲出→城市收束。不是固定模板。

先 Workbench，必要时 Eevee；先 blocking 后 polish。完整视频预演统一 2560 × 1440；提高尺寸不能替代模型质量检查。用户确认预演后 `LOCK GEOMETRY + CAMERA`。Cycles 不是默认最终动画渲染器，优先仅对3–4个关键状态做低/中低 samples + denoise 光影参考；H3 始终使用 Blender RGB 预演/渲染视频。

**设计/修改 Camera 或预演前必须读取 [references/camera-design.md](references/camera-design.md)。** 其中保留 Shot Planning、FPV 档位、Camera Rig/Target、焦距、Roll、角速度、Shot Manifest、代表帧、迭代顺序、确认 A 和 Cycles 细则。

研究阶段须实际查看网上参考图；用户已同意生成的建模设定图可在建模前展示，须注明其为概念参考。它们不属于 Blender 预演截图，不能用下述画布限制跳过研究。预演内部检查若工具受限，应寻找不发布到画布的可用看图方式；确实无法查看则报告受限，不能宣称 QA 通过。

**预演阶段画布限制（强制）：** 制作、检查、修改 Blender 预演及确认 A 期间，禁止把视频关键帧、白模截图、测试渲染帧、渲染序列或接触表放到画布。它们只作为项目内的中间文件用于内部检查和编码；不得通过会自动创建画布节点的出图方式提取，也不得先上画布再删除。画布仅交付预演视频，检查问题用文字和时间点说明。此限制不取消代表帧检查，也不影响确认 A 之后生成并展示3–4张风格关键状态图供确认 B。

### 5.3 RGB → 一致风格关键帧 → H3
**进入 GPT Image/H3、最终 QA 或失败修复前必须读取 [references/failure-recovery.md](references/failure-recovery.md)。**

确认 A 后锁定 Geometry + Camera，保留通过检查的 Blender RGB 视频。所有风格（含线稿、动漫、赛博朋克）均使用这条视频输入路线；不得退化为只用图生成视频。

严格顺序：

1. 建立本片唯一的 **Visual Bible**：时间、天气、天空、太阳世界方向、主光、阴影、材质、色温、曝光、色彩分级和画风。
2. 必选视频第 0 秒及结束时刻对应的 Blender 画面，再按空间变化选择中间 1–2 个不同状态，共 **3–4** 张；逐一风格化，不以原始白模图替代。实际抽帧与秒数映射遵循 failure-recovery.md。向用户展示及写入 H3 Prompt 时仅用“第 X 秒”描述，不用“首帧”“尾帧”等角色称谓。
3. 用最有代表性的 Blender 帧 + Visual Bible 生成 **Master Style Frame**；内部检查通过后作为视觉母版，不单独请用户确认。
4. 其余每张图必须**同时输入各自 Blender 帧 + 同一 Master Style Frame + 同一 Visual Bible** 做 **Style Propagation**。构图听各自 Blender 帧，外观继承母版；不得复制母版视角，不得独立从零定调或逐帧接力累积漂移。
5. **自动 Style Consistency QA**：逐帧对照自己的 Blender 帧、母版和 Bible，再对整组交叉检查。检查天空/时间/天气/太阳与光线方向/建筑材质/色温/曝光/色彩分级/主体身份/建筑结构/整体画风。
6. 不一致时只重做异常帧，保留已通过帧；修复后重查异常帧及全组一致性。未通过不得交付为待确认成品或进入 H3。
7. 全组通过后一次展示全部最终关键帧作为**确认 B**；用户确认该组具体版本后才 **LOCK STYLE**。
8. 验证三类输入后，**仅使用 H3 全能参考模式（all-purpose multimodal reference）**调用 H3：**Blender RGB 视频 + 3–4 张已确认一致风格关键帧 + Astra 模块化 Prompt**。

每张图保持 Camera Angle、Perspective、Composition、Major Geometry、Landmark Identity、Object Placement、Architectural Silhouette；材质、光影与色彩变化必须服从统一 Bible。
写实优先 `Identity > Geometry > Spatial Accuracy > Camera > Lighting > Beauty`；强风格 `Identity > Composition > Camera > Visual Impact > Style > Fine Geometry`；主体身份始终不可丢。

生成 H3 Prompt 前必须读取 [references/h3-prompt.md](references/h3-prompt.md)，其中已融合 h3-prompt-expert 的建筑适配框架和全部 11 份参考文件（非执行模式已隔离至维护备份），无需安装、调用或运行时读取外部 Skill。执行素材适配诊断→已确认约束复用→必要澄清→多模态六字段 Prompt→自检。RGB空间、主体身份、锁定风格与 Camera 时序写入字段内部，替代旧的自由段落模板。H3 默认生成一次。
运行 `scripts/validate_output.py previs.mp4 --previs --decode-check` 强制检查 2560 × 1440 预演尺寸；结合 manifest 参数检查 RGB 输入及最终视频的尺寸、FPS、时长、实际帧数和编码；视觉一致性由 Astra 看图检查，不能用文件检查代替。

## 6. 两个强制确认点与状态
A：展示 `previs.mp4`，确认建筑/城市准确性、展示重点、FPV 路线、速度和入口；确认后 `LOCK GEOMETRY + CAMERA`。
B：仅在自动 QA 全组通过后，一次展示全部 3–4 张最终关键帧，标明状态/时间，说明它们共同作为 H3 视觉参考；确认后 `LOCK STYLE`。不增加母版确认点。

把阶段、文件版本、QA 结论和用户确认记录到 `shot_manifest.json`。用户说“下一步”时先读取状态，完成缺失的当前阶段，不跳过 QA 或 A/B。已明确确认同一版本的素材不重复询问。

H3 前置条件：A 有效；RGB 来自锁定的 Blender 场景和镜头且文件/视觉检查通过；3–4 张最终图对应同版 Bible 并全组 QA 通过；B 对应当前素材版本；Prompt 与这些输入一致；当前实际选择全能参考模式且接口支持视频 + 3–4 图 + Prompt。禁止使用首尾帧模式、单图起止约束模式或因图片时间位置自动切换模式。任一条件缺失，先补齐；不伪造支持或悄悄省略输入。
确认后修改模型/镜头会使受影响 RGB、风格帧及确认失效；修改风格帧/Bible 会使该组 QA、B 和 LOCK STYLE 失效。只回滚受影响层，按引用细则复核。

## 7. 回滚原则
身份/模型错→Reference/Geometry；比例/入口/空间错→Geometry/Layout；路线/速度错→Camera/Previs；光影参考错→Lighting/Cycles；风格不一致→只修异常 GPT Image 帧；RGB 与关键帧均正确但 H3 漂→H3 Prompt/Conditioning。
不得为局部问题整链重跑。自动异常帧修复默认最多两轮；仍不通过则报告具体阻塞，不继续消耗生成额度或请求用户把失败 QA 当成通过。H3 默认一次，后续按用户反馈分层处理。

## 8. 完整工作流

```text
用户需求 + 用户参考图优先
 → 主动网上搜图 + 实际看图 + 记录结构依据与缺口
 → 资料充足？是 → 参考准入
              否 → 询问是否生成参考图 → 同意后用内置提示词补图并检查
 → 参考准入 → 内部草模 → 分层精准建模 / 同模型比例校准
 → 模型质量检查（草模不可直接交确认 A）
 → FPV Camera / Rig / 一镜到底
 → Workbench / Eevee RGB 预演 + 文件/视觉 QA
 → 确认 A → LOCK GEOMETRY + CAMERA
 → Visual Bible
 → 第0秒 + 中间1–2个状态 + 结束时刻，共3–4张（可选 Cycles 参考）
 → Master Style Frame（内部检查）
 → 其余帧：各自 Blender 帧 + Master + Bible → Style Propagation
 → 自动 Style Consistency QA
      未通过 → 只修异常帧 → 全组复查
      全通过 → 一次展示全部最终帧 → 确认 B → LOCK STYLE
 → Blender RGB 视频 + 已确认的 3–4 帧 + Astra 模块化 Prompt
 → H3 全能参考模式（默认一次） → 文件/视觉 Final QA
 → final.mp4 + project.blend + RGB 视频 + 风格帧 + manifest
```

## 9. 最终产品原则

1. **先准确，再漂亮。** 写实地标的身份与关键结构优先。
2. **先镜头，再渲染。** H3 参考锁定 Blender RGB 的轨迹、时序和空间。
3. **先预演，再高成本步骤。** 先把空间和运动验证清楚。
4. **Cycles 是可选光影参考。** 不默认完整高采样动画。
5. **全片一个视觉世界。** Bible、母版、传播和 QA 缺一不可。
6. **默认一镜到底、电影 FPV。** 可以设计视觉可信但现实困难的路径。
7. **两个确认点。** A 锁定模型/镜头，B 锁定全组一致风格。
8. **已确认成果按版本保留，失败分层回滚。**
9. **保留可编辑 Blender 资产。** 不只交付视频。
