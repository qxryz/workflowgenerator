本文件是本包 H3 提示词阶段的唯一入口。已将本地 h3-prompt-expert 主框架与全部 11 份 references 内容纳入 `h3-prompt/`，不调用其他 Skill，也不依赖该 Skill 的安装路径。主文件仅保留入口。下列建筑适配规则优先于子文件中的通用默认值和案例。

每次编写 H3 提示词先读本文件，再读以下包内文件：

- [源视频保留](h3-prompt/editing-preservation.md)：提取空间、Camera、时序与遮挡保留规则；依下文区分外观可改范围。

## 与建筑流程统一的约束

1. 默认任务已经确定：Blender RGB 视频 + 已确认、QA 通过的 3–4 张风格图 + Prompt，必须选择全能参考模式并使用多模态六字段格式。输入不足返回对应阶段；不得建议跳过 RGB 走纯文生。
2. 使用当前 manifest 的时长（默认 10–15 秒）、FPS、Camera 路线和 16:9 画幅。2560 × 1440 是 Blender 预演尺寸；H3 输出参数与可用多模态组合在运行时核对。子文件“24 FPS、原生立体声、可用画幅”等是来源技能的默认描述，不是所有接口的能力保证，不作为虚构参数依据。
3. A 已锁定模型/Camera，B 已锁定整组风格；已有明确答案直接复用，不再问用户选路线、风格或是否确认母版。只有新增缺口会改变已确认内容时才针对该缺口提问；无新缺口直接写 Prompt，不增加第三个固定确认点。
4. 默认一个 `[Shot 1]`，在内部按时间段描述接近、绕行、揭示和落点，不用多个 Shot 把一镜到底变成剪辑。准确时间来自 Blender manifest，而非凭空创造更激进运镜。
5. RGB 是几何、构图、透视、遮挡、轨迹、节奏的依据；Visual Bible 和风格帧是材质、天空、天气、色温、曝光及画风的依据。不能套用“源视频所有颜色、材质、光照不变”而抵消已批准的风格化。Workbench studio light 不能强行覆盖 Bible 的世界太阳方向。
6. 写实优先身份/几何/空间/Camera，再光影和美感；强风格仍保持地标轮廓、位置和主要构件，仅在获准外观层变化。多地标用独立身份描述，避免互换、合并、复制或为了同框移动地标。
7. 不自行加入人物对白、字幕、Logo、UI、片尾卡、硬切或节奏闪帧。自然环境声作为可逆默认，未要求配乐时 `non_diegetic_music: N/A`。音频条目只有真实提供且获准使用时才定义；空预演声轨不等于用户要求最终静音。
8. 最终 `h3_prompt.txt` 只放六字段正式提示词。参考适配诊断、审批记录与自检另写 manifest 或 `h3_prompt_qa.json`，不能混入提交文本。模板字段必须按实际资料填满，不残留占位符。

## 内部执行顺序

### 1. 诊断风险与素材职责

逐项检查所有实际输入，写明“能约束什么、不能约束什么、是否足够”。

| 素材 | 适配判断 |
|---|---|
| Blender RGB 视频 | 确认 A、完整路径、帧序、原生预演尺寸与实际文件对应；能提供 Camera 与结构，不默认代表最终画风 |
| 每张已确认风格帧 | 标记状态、时间、源 Blender 帧号与图像哈希；检查身份、构图及统一 Bible；不是新机位要求 |
| Visual Bible | 用文字内嵌其可见规则；不是不存在的上传图像 |
| 额外声音/文字参考 | 只有需求存在才加入，核实其授权用途与实际覆盖范围 |

未实际上传的图片不能定义为可供 H3 读取的资产。来源参考照片已在建模阶段消化，不自动追加到最终风格列表造成冲突。

### 2. 必要澄清

素材充分时直接使用当前已确认版本；部分充分时指出具体未覆盖项，并给出保留现有成果的修复方式。最多聚焦 1–3 个当前问题，不照搬通用菜单重新询问所有输入。

涉及补生成关键帧则依原有版本失效与确认 B 规则处理；不以“提示词专家流程要求”为由额外要求确认。没有实际支持视频加多图的入口时报告能力缺口，保留产物。

### 3. 写六字段 Prompt

字段名保留英文，正文默认中文。`<Video 1>`、`<Picture N>`、`<Subject N>` 是提示词内部引用名；上传完成后将它们与真实工具资产 ID 对应，不把这些字段冒充 API 参数。每个真实素材定义一次，正文中按用途再次引用。

```text
subject_definitions:
<Subject 1>: {主要地标身份、比例、轮廓、标志构件和位置关系}。
{其他地标逐一分配稳定 Subject 编号；不需要时删除本行。}
<Video 1>: 已确认的 Blender RGB 预演，控制空间、构图、透视、遮挡、摄影机轨迹、速度曲线与时间顺序；其基础 CG 外观不是最终美术标准。
<Picture 1>: 第0秒的 {空间状态} 已确认风格参考，控制该状态的材质、天空、天气、曝光和画风，保持对应 Blender 构图。
<Picture 2>: 第{中间秒数}秒的 {空间状态} 已确认风格参考，与 Picture 1 共用同一 Visual Bible。
<Picture 3>: 第{结束秒数}秒结束附近的 {空间状态} 已确认风格参考。
{若选4张，在时间顺序上增加另一个中间状态并重编号，使 Picture 4 对应结束附近；不能省略任何一个时间端点状态。}

summary: {时长}秒、16:9 的 {主体/地点} 建筑景观，{写实或已确认风格}，一个连续 FPV 镜头。以 <Video 1> 保持空间运动，以已确认图片统一外观，结尾落在 {真实 Camera 终点构图}。

retention_analysis: 保持 <Video 1> 的地标位置、主要比例、建筑轮廓、开口连接、前后遮挡、透视变化、摄影机路径与节奏，不增删核心构件。外观按 <Picture 1> 至 <Picture N> 及 {Bible 的时间/天气/世界太阳方向/材质/白平衡/曝光/调色规则} 统一。仅允许 {批准的外观变化和室内外自然过渡}，不继承与目标风格冲突的预演 CG 表面。

detailed_description: [Shot 1] 全程连续，不切镜。{开场构图与可见主体}。{按 manifest 写连续时间段及运动：接近/侧绕/升降/入口/揭示/落点；每段显式说明遵循 Video 1，并在对应状态引用 Picture 编号。} 各时间段是同一镜头的连续阶段。保持地标身份、位置、构件与材质一致；无瞬移、随机变焦、弯墙、复制建筑、门窗漂移、纹理闪烁或无理由改变天气/太阳。经过开口才进入内部，不穿实体墙。{有文本需求才追加唯一文字清单与禁止额外文字规则。}

overall_soundscape: {与地点及运动匹配的克制环境声；如有用户指定声音则准确体现其用途，不添加未要求对白。}

non_diegetic_music: N/A
```

### 4. 写实与强风格填充

- 写实：在视觉规则中写清各区域真实材质、反射/粗糙关系、可信阴影和间接光、受控高光、空气透视。禁止用“电影感”一个词替代具体规则。无资料的内部不得声称真实复原。
- 强风格：保留相同六字段与运动约束，仅将批准的笔触、色板、材质和设计变化填入 summary、retention_analysis 与 detailed_description。不得把“风格化”写成允许随意重构主要几何。
- 新增文字：按文字规则记录精确拼写、位置和是否允许其他字；参考中出现但用户不要求的无关品牌/水印不复制。参考图不足以支持新增设计时走已有补图与 B 流程。

## 提交前自检

逐项核验并记录证据，失败则修改 Prompt 或回到对应素材层：

- 六字段齐全；正文描述具体可见，不是空泛风格词；没有未填变量。
- 视频与全部 3–4 张图片实际存在、已上传、用途明确、时间对应准确；引用无缺失编号或虚构音频。
- 已实际选中 H3 全能参考模式；图片标签只用“第 X 秒 + 空间状态”，不包含首帧/尾帧角色称谓或 first/last-frame alignment 指令。第0秒和结束状态以及中间1–2个状态全部已风格化。
- 默认只一个 Shot，阶段时间有序、连续且不超出 manifest 时长；没有要求一镜到底又写切镜。
- A/B、QA、RGB、Bible 和图片版本一致；已确认的内容不被新创意覆盖。
- retention_analysis 明确保留几何/Camera、允许目标外观变化；没有把 CG 光照与 Bible 同时写为互相冲突的权威。
- 多地标身份与空间不互换；局部细节不漂移；阴影按世界方向而非固定屏幕方位。
- 声音、配乐、对白、文字相互一致，未无端增加片尾卡或包装；接口能力已核实。
- 通过后保存提示词和哈希，按原流程默认只提交一次 H3。Prompt QA 不能代替最终视频 QA。
