# 建模与真实参考重建

开始建模前先读本文末“主动搜图与建模准入”；需要补生成参考图时使用本文内置提示词。

## 5. 准确性原则：与 Previs 兼容的“分层精准”

“精准”不等于把所有像素级细节都在 Blender 中高模重建。

### Blender 必须精准的部分
对真实建筑、地标和用户指定主体，优先保证：

- 主体身份；
- 整体轮廓；
- 长宽高比例；
- 标志性建筑构件；
- 主要开口、门、窗、塔、穹顶、屋顶等位置；
- 建筑群之间的空间关系；
- 相机经过区域的几何；
- 室外到室内的主要空间连通；
- 与 FPV 路线直接相关的净空、入口宽度、转弯空间和障碍物。

### Blender 可以简化的部分

- 远处不可辨认的立面细节；
- 每块砖、每个铆钉、每个雕像；
- 不影响轮廓的微小装饰；
- 远离镜头的高密度重复件；
- 最终由 H3 重绘的复杂材质和微观纹理。

### 精度随镜头距离变化
遵循：

> 离摄影机越近、停留越久、越影响主体身份 → Blender 几何越精细。

> 越远、越短暂、越不影响轮廓 → 越允许模块化和简化。

### 用户参考图优先级
用户上传参考图优先级高于普通网络参考；但若参考图存在明显事实错误或彼此冲突，必须指出差异并让用户决定：

- 严格按用户图；或
- 按真实资料修正。

不得静默篡改用户已确认的设计。

## 6. 真实资料研究与参考重建

当主体是现实存在的建筑/城市地标时，默认进入“真实参考重建模式”。

### 6.1 参考资料目标
主动寻找并整理：

- 正面；
- 侧面；
- 背面；
- 鸟瞰/屋顶；
- 平面或结构示意；
- 标志性局部；
- 内部空间；
- 入口；
- FPV 预计经过区域；
- 尺寸或可推导的尺度信息。

### 6.2 可见事实与推演分开

- 参考图能直接看到的内容：按事实还原。
- 被遮挡部分、不可见屋顶、内部未公开区域：标记为“推演/合理补全”。
- 不把概念图标题、旅游宣传图或 AI 图直接当作工程投影。
- 多张参考互相矛盾时，优先寻找更可靠来源；仍无法判断时询问用户。

### 6.3 比例与坐标

- 建立统一坐标系；
- 记录前向方向、Z 轴、地面标高、主要尺寸；
- 必要时将主要长度、宽度、高度和关键构件位置归一化，便于检查相对比例；
- 使用现实尺度时，尽量统一 Blender Units；
- 在使用 bevel、boolean、physics 或依赖几何尺寸的 modifier 前应用 scale。

## 7. Blender 连接与执行层

优先使用可用的 Blender 集成；如无法直接连接，可使用本地文件桥接方案。

### 7.1 角色分工

- Codex/Astra：planner / director；
- Blender `bpy`：场景执行层；
- Blender 集成或本地桥接：只负责传递执行请求，不负责创意判断。

桥接层只负责把请求送进 Blender，不负责创意判断。

### 7.2 操作前必须检查
在任何修改之前：

- 检查 Blender 是否运行；
- 验证连接是否真实可用；
- 连接文件/目录存在不代表实例存活；
- 用只读检查请求确认当前连接；
- 读取当前 `.blend`；
- 读取 scene；
- collections；
- objects 名称和类型；
- cameras；
- active camera；
- frame range；
- FPS；
- units；
- save path；
- render engine；
- 已有用户成果和已确认版本。

### 7.3 保存与安全

- 默认保留用户当前场景，除非用户明确要求替换；
- 大改前另存新 `.blend`；
- 不覆盖无关用户文件；
- 生成内容放入语义化、编号 collection；
- 交互修改时，每个相对完整的编辑批次前压入 Undo；
- 不依赖 Blender 自动 `.001` 后缀识别关键对象；创建后立即保存对象引用或稳定命名；
- context-dependent operator 前显式设置 mode、selection、active object；
- 只有结构化动作无法实现时才使用任意 `bpy` 代码；代码应作用域明确并返回精简结构化结果；
- 代码成功不等于视觉成功，必须通过截图/代表帧/预演检查。

### 7.4 推荐 Collection 结构
可使用：

- `01_ENVIRONMENT`
- `02_SUBJECTS`
- `03_MOTION_RIGS`
- `04_FX`
- `05_CAMERAS`
- `06_LIGHTING`
- `07_REFERENCES`

重要多部件主体使用 root empty；需要独立运动的门、机关、旋转件等使用嵌套 pivot。

## 8. Blender 建模策略

### 8.1 先大形，后细节
先完成：

- footprint；
- overall height；
- clearance；
- subject scale；
- silhouette；
- articulation；
- openings；
- contact；
- camera readability。

再增加真正影响镜头的细节。

### 8.2 为镜头空间建模，而不是为对象数量建模
环境应优先围绕：

- 可通行区域；
- 摄影机 sightline；
- 前景 / 行动平面 / 背景三个深度层；
- 视差；
- 入口/孔洞/通道；
- FPV 转向空间；
- 遮挡关系。

城市不要为了“丰富”而堆大量在预演分辨率根本看不出的对象。

### 8.3 重复模块
窗户、柱子、台阶、路障、路灯、车辆、建筑模块等优先使用实例、共享网格、阵列或程序化重复。

### 8.4 建模可编辑性
优先使用：

- primitives；
- curves；
- modifiers；
- parents；
- constraints；
- named rigs；
- instances。

避免把整个场景烘死成难以修改的单一网格。

### 8.5 真实地标的结构校准
需要时从同一真实模型输出：

- 正视；
- 侧视；
- 俯视；
- 鸟瞰代表视角。

比例反馈必须回到真实几何修改；不得为了“看起来对”单独摆三套不一致模型。

## 29. 已有成果复用原则

不要重做用户已认可的部分。

- 已有合格 `.blend`：复用资产；核实参考依据和模型质量记录，缺失时补查，满足当前主体和路线后从镜头阶段进入；
- 已有模型且 Camera 未做：从 Camera Planning 开始；
- 已有 Camera Preview 且用户已确认：验证 RGB 素材后进入 Visual Bible / Style；
- 已有风格图并确认：检查其来源、Bible、整组 QA 与当前 Blender 版本；证据仍有效就复用，不重新生成或重复确认；缺少一致性 QA 则先补检查，不自动把旧确认视为新组确认；
- 用户只要求改镜头：保留模型；
- 用户只要求改风格：保留 Blender Geometry + Camera + RGB 视频（若仍匹配）。

## 主动搜图与建模准入（建模前执行）

### 搜索、查看、形成依据

收到主体需求即执行，不等待用户说“去找参考图”。先分清具体真实建筑、城市区域、虚构作品主体或原创概念；名称有歧义且会选错主体时先确定所在地/版本。原创环境也主动研究用户所需建筑类型与空间元素，把类似案例标为设计参考，不冒称目标的实景。

- 查询组合：主体准确名称 + 城市/国家；当地名称或英文别名 + facade/side/aerial/roof/entrance/interior/floor plan；中文对应正立面、侧立面、鸟瞰、屋顶、入口、内部。仅搜索对当前路线有用的视角。
- 用户给图也要查看并提取信息；网络补充不能静默覆盖其已指定设计。真实建筑优先官方网站、建筑师/博物馆资料、可信实景摄影；排除同名建筑、缩略图误认和未经标明的 AI 图。
- 使用当前可用的网页/图片搜索与视觉查看工具。打开来源页面，查看足以辨认结构的图像；搜索摘要不能替代图像观察。工具不可用或网页打不开应如实记录，不伪造“已搜集”。
- 可下载时存入项目 `references/source_images/` 并记录来源；不能下载时保留可访问图像资源及查看记录。仅有网页链接但无法查看图像，不能算已覆盖该视角。
- 按参考覆盖而非固定张数判断：重复转载同一正面照不会补齐屋顶或入口。外观环绕通常需要主立面、侧面和屋顶信息；进入内部的镜头还须核实入口尺寸关系及相连空间。
- 缺口出现后进行一次有针对性的补搜：换当地名/来源/缺失视角。关键缺口仍存在就询问，不能无止境搜索或直接用想象替代。

在 `reference_manifest.json` 中保存实际记录，不预填通过：

```text
subject: 名称、地点/作品版本、真实/概念属性
sources[]: id, user/web/generated, source_page, image_resource,
           local_path_if_available, viewed, viewing_evidence, view,
           observed_features, reliability, inferred_regions
coverage: silhouette, proportions, landmark_features, roof,
          openings, route_clearance, interior_if_needed
missing: 每项缺失内容、是否影响身份或计划路线
generation_choice: pending/approved/declined, 用户消息依据, 授权补图范围
generated_refs[]: 源图ID, 实际提示词, 文件, 推演说明, 一致性检查
reference_gate: pass/blocked, 判断依据, 可建模范围, 版本
```

`viewing_evidence` 记录工具结果标识及实际看见的具体特征，例如“东立面三组拱窗、入口位于基座中段”，而非只有“看过了”。每个主要模型构件应能追溯到图像或已获准的推演范围。

### 何时必须询问是否生成参考图

主体身份、主要比例、标志构件或镜头经过区域缺少依据，且无法通过针对性搜索补足，属于资料不足。看不见且不会入镜的微小装饰可暂不建模，不为了它额外生成整套图。

先整理已有图片、缺口与拟用的补图提示词，使用户知道会补什么，再询问：

> 已找到 {已覆盖的视角}，但 {具体缺口} 仍缺少可靠图片，会影响 {建筑部件或镜头区域}。是否先生成用于建模的参考图来补足？生成部分会标明为推演，不能作为真实建筑资料。

用户同意后才生成；不回复不视为同意。已在当前任务授权同一范围的补图无需重复问。拒绝后由用户补图或决定调整路线；等待期间可以整理已证实的结构和参数，但不得执行依赖缺失资料的建模。

若用户要求完全真实复原，生成图无法恢复未公开事实；说明这一点，由用户选择接受有标注的推演或提供真实资料。用户允许生成参考图不等于允许改变已知建筑身份。

### 参考准入

以下全部满足才进入实际建模：

1. 已实际查看与当前需求相关的图片，并有可追溯的记录。
2. 对入镜主体形成可执行的形体、比例、构件和路线空间说明。
3. 关键缺口已由可靠资料补足，或经用户同意由生成设定补足；其推演属性清楚。
4. 不同视图的主体、比例和连接关系无尚未解决的冲突。

缺口解决不必另设常规用户确认；自动检查通过后按已授权范围继续。真实资料、生成设定、实际 Blender 渲染在文件和说明中分别标记。

## 内置参考图提示词：建筑与空间版本

以下提示词已融合参考仓库的方法并改编为本 Skill 的建筑任务；执行时直接使用本文，无需读取 GitHub。将花括号字段替换为当前主体、已查看图片与实际缺口，不把案例中的飞船部件、固定数量或三镜头时长带入本流程。

按需选用，不要求所有项目都生成三视图或内部图。每次生成应实际输入相关已收集图像，而不只在文字里声称引用。未收集到目标图像时，用用户授权的设计条件生成“概念设定”，不得声称忠实还原。

### A. 建筑外观设定

```text
制作 {主体} 的建模设定图，依据附件 {参考ID}。锁定 {可证实的轮廓、比例和标志构件}。用完整斜视角呈现体量，补充 {缺少的局部} 的放大视图。光照中性，边界清楚，无强雾遮挡。仅在 {已授权区域} 补设计；另附说明区分观察事实与推演。禁止更换建筑类型。
```

### B. 多方向对齐参考

```text
将 {主体} 表达为正面、侧面和俯视的概念参考，同属一个设计。使用 {统一轴向、尺度基准} 对齐基座、屋顶和 {关键构件}；避免透视夸张，保持各图构件数量与位置可互相核对。遵守附件 {参考ID}，缺失面仅按 {授权范围} 补全。输出用于建模的设定，不标称实测图纸。
```

### C. 通行空间与局部构造

```text
为 {入口/中庭/通道} 生成可读的空间关系参考，匹配附件中的外部体量和开口位置。表达 {路线起点至终点} 的连接、转弯和净空；放大 {需建模的局部}。已有依据不可改动，未知区域仅在 {授权范围} 推演并另附标注。不虚构其历史用途或工程尺寸。
```

生成后先检查各图一致性：主体身份、基座/屋顶站位、主要比例、入口及连通关系。发生冲突时修异常图；不能把矛盾交给 Blender 随意选择。最多两轮局部补图修复，仍不成立就报告冲突并请求方向，不无限生成。

这些是建模前设定，与确认 A 后的 GPT Image 风格帧分工不同。生成设定只辅助建模；真实几何形成后必须从同一模型重新渲染校准视图。图片上的数字和标签也要核对，生成的标签不是测量证据。

方法来源（供溯源，非运行依赖）：[分阶段提示词](https://github.com/375432636/gpt6-blender-video-skill/blob/main/skills/reference-to-blender-video/references/prompts.md) 与 [案例 Prompt 01–04](https://github.com/375432636/gpt6-blender-video-skill/blob/main/docs/prompts-and-timing.md)。上面是建筑场景改编，不是原文逐字复制。

## 从参考进入实际模型：防止草模成为确认 A 成品

草模用于内部试验体量和路线。得到可播放视频不代表完成建筑重建。建立 `model_qa.json`，逐项记录图像依据、模型对象/参数、观察结果与待修问题：

| 项目 | 确认 A 前要求 |
|---|---|
| 主体辨识 | 不依赖标题也能由轮廓与标志构件辨认目标；不能只有泛化方盒 |
| 比例 | 根据有依据的尺寸或相对比例校准长宽高；标明估算范围，不编造精度 |
| 关键构件 | 屋顶、塔楼、立面分段、主要开口等按入镜距离建出实际形状与位置 |
| 空间 | 建筑相互位置、基座、地面与路径通道合理；入口不得画在封闭实墙上 |
| 近景 | 镜头贴近或停留处有足够几何层次；不能指望 H3 补救缺失的核心构件 |
| 对照 | 用同一模型的校准视图对照参考；发现比例错就改模型，再检查受影响视角 |
| 可编辑性 | 语义化部件、实例、修改器与 Camera 保留，不为某一视角伪造另一套模型 |

只有与当前路线相关的必检项全部通过，才输出待确认 A 的完整预演。检查失败时回到对应部件，保留合格成果；若问题根源是缺资料，返回资料不足询问分支。不得把没有完成的模型交用户确认后再声称已经锁定。

使用 Workbench 可以降低渲染成本，不能降低身份和几何标准。材质与光照可朴素，但应清楚显示构件、遮挡和入口。内部对照图依旧遵守不发布到画布的要求；无法实际查看时不能宣称质量检查已完成。
