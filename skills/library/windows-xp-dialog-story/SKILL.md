# Windows XP 风格弹窗故事

生成独立的 Windows XP Luna 风格弹窗图，并支持把弹窗变成可读的叙事对象：弹窗随事件出现、累积、层叠、报错、变化和结算。原有静态弹窗能力继续保留；视频扩展负责把弹窗状态、进度、失败和完成组织成有时间顺序的视觉事件。用户可以提供简短创意、静态弹窗素材、参考图片，或组合提供。

## 步骤 0：确定范围与输入

先判断用户要一张静态弹窗、弹窗玩法视频，还是两者都要。视频任务必须按以下阶段推进，不能直接跳到视频生成。

**对话节奏是强制要求：**每个用户回合只推进一个阶段。只询问当前阶段的下一项输入，然后停下来等待用户；不得一次性列出所有未来问题、倾倒完整制作简报，或在用户尚未回复当前阶段前提前进入后续阶段。每个阶段完成后，只简短说明已完成什么，并询问下一项必需输入。

1. **弹窗资产阶段：**先根据创意设计并生成所需的弹窗家族，包括报错、警告、进度、中断和结算状态；只有语义需要的状态才生成，并统一标题栏、字体和窗口比例。生成后停下来，只询问角色素材。
2. **角色素材阶段：**请用户上传角色参考，或明确确认不需要角色。只要视频依赖特定人物 / 角色，就不得凭空创造其身份。收到后停下来，只询问剧本或剧情大纲。
3. **剧本阶段：**请用户上传剧本、对白或场景大纲。用户提供的口播和屏幕文案必须原样保留。收到后停下来，只总结下一项尚未确定的制作选择。
4. **互动时间线阶段：**把角色动作和剧情节点对应到弹窗出现、叠加、移动、进度变化、中断、淡出或结算；只在需要时询问下一项缺失的时长、画幅、场景参考、语言、字幕或结尾选择。
5. **视频阶段：**只有弹窗资产、角色输入，以及剧本或明确的“无剧本”决定都具备后，才生成弹窗玩法视频。

如果视频确实不需要角色或剧本，必须在对应阶段请用户明确确认后才能跳过，不得静默省略。如果必须生成视频但缺少时长或画幅，只在流程进入制作选择阶段时单独询问该问题。

用户明确提供的可见文字必须逐字保留。不得凭空添加有后果的系统结论、破坏性操作、法律 / 安全提示或没有语义依据的控件。

## 步骤 1：静态弹窗设计

静态任务先判断处理中、完成、警告、错误、确认或输入 / 结果预览，再决定最少且有意义的标题、正文、图标、按钮、层级和布局。默认使用一个居中的 4:3 横向弹窗，干净隔离背景；不得承诺输出透明通道。使用蓝色 Luna 标题栏、经典凹凸边框和清晰的中文或用户指定文字；不得出现桌面、任务栏、硬件或周围风景。

默认使用当前可用的图像能力。若用户明确指定其他图像模型，先检查其能力，再遵循用户选择。生成失败时先针对可能原因调整并重试一次；仍失败则切换其他兼容的可用模型。如果用户明确要求透明 PNG，应说明生成结果不保证带 alpha 通道；只有当前可用独立抠图或后处理能力支持时，才进行后续处理。

## 步骤 2：弹窗视频玩法库

视频扩展是**弹窗物理化动作短剧**，不是在对白场景上贴 UI 贴纸。若用户要求复古质感，应优先采用明显的早期 DV / 2000 年代初电视剧影像，而不是精致的现代电影广告感。干净隔离的静态弹窗只属于资产阶段；当用户提供场景参考时，最终视频通常应把角色和弹窗放回该现实空间，或放进经过明确变形的系统空间。

遵循以下视觉规则：

- 把弹窗当作扁平但有实体感的物件，具备深度、透视、前后遮挡，并能与角色或道具发生碰撞。
- 每个主要弹窗都要绑定一个可见动作或剧情节点，例如撞击、打断、回避、未回复、扔物、推开或和解。
- 建立反馈循环：动作 → 弹窗反馈 → 动作升级 → 更密集的弹窗反馈。
- 干净隔离背景只用于制作可复用弹窗资产；当用户提供场景参考时，不作为最终视频的默认场景。
- 时长允许时，至少安排一个动态升级高潮和一次清楚的系统状态转场。

视频围绕清晰的状态弧线构建，不要堆叠互不相关的界面镜头。可根据创意使用以下玩法：

1. **错误累积：**可见事件发生后，连续出现错误或警告弹窗，让空间逐渐拥挤并形成升级压力。
2. **层叠与释放：**层层叠加的弹窗形成视觉压力；转折后，次要弹窗淡出、移开或收拢，露出一个决定性的核心弹窗。
3. **动作驱动进度：**进度条或状态数值因画面中的动作发生变化。变化必须看得见、时间上有因果，不要无理由跳动数字。
4. **系统中断：**当创意需要时，可用卡死、崩溃、重启或黑屏打断动作，再回到干净状态或终局状态。
5. **结算弹窗：**用一个完成或结果弹窗收束前面积累的状态。文案必须来自用户或创意依据，不能包装成没有根据的真实系统结论。
6. **系统载体转场：**当创意需要时，把场景变成蓝屏 / 崩溃画面、经典桌面式系统空间、加载虚空或其他系统状态，再回到现实。这是场景变形，不是完整桌面复刻。
7. **余韵与反高潮：**以黑屏、最终完成进度或系统通知收尾；如果有助于笑点，让结算弹窗解决系统状态，而角色的狼狈、疲惫或尴尬静止制造最后反差。

当创意需要动作时，使用多样的物理空间镜头语言：用远景展示弹窗密度，用中景交代动作关系，用反应近景和局部插入放大荒诞细节，在冲击点快速平移或推近，并在系统失败时短暂定格。避免整条视频重复同一个景别或运动。通过前后景位置和真实遮挡让空间纵深可读。始终保证关键弹窗可读；快速运动只用于转场或冲击节点。

## 步骤 3：时间与声音

把弹窗出现、撞击、点击、状态改变、进度变化、卡死、淡出和最终结果映射到节拍时间线，建立开始、动作升级、转折和结束四个阶段。把系统声音作为节奏的一部分：弹窗点击音、报错音、崩溃警报、卡死时的静默和最终确认音，应在用户要求或生成声音时与重要动作落点同步。除非用户指定其他语言或声音方向，口播默认使用自然的台湾腔国语，不使用播音腔或大陆新闻腔。若有用户音乐，让动作冲击和弹窗爆发跟随音乐结构重音。用户未要求字幕时，不添加字幕。

## 步骤 4：参考贡献

按每个图片参考的明确作用使用素材：完整剧照可承担场景、人物关系、机位和整体影调；角色资产表承担身份连续；弹窗图承担 XP 外观和状态设计。多张弹窗图应作为分阶段的状态家族使用：先出现报错 / 警告，再在剧情节点引入进度 / 中断，最后把完成 / 结果弹窗留给结算；除非剧情明确要求，不要让所有弹窗从开头同时出现。除非用户明确要求，不转移参考中的偶然人物、场景、Logo 或文案。

## 步骤 5：规划、确认与制作

视频的阶段性输入未完成前，不得生成最终视频。弹窗资产、角色素材和剧本或明确的“无剧本”决定齐备后，才给出节拍方案；不得一次性展示整个未来流程或收集所有剩余选择。每次只确认下一项会显著影响结果的时长、画幅、文字或结尾选择，然后等待用户回复。先生成具有统一视觉语言的可复用弹窗 / 关键帧素材，再按时间顺序生成或组装视频。重复出现的弹窗要保持标题栏比例、字体、图标逻辑和按钮位置一致，同时允许内容随状态变化。

视频默认使用 MiniMax-H3。若用户明确指定其他模型，先检查其能力，再遵循用户选择。生成失败时先针对可能原因修正并重试一次；仍失败则切换其他兼容的可用模型，不对同一模型反复尝试。

如果结果丢失弹窗可读性，先调整尺寸、时间、遮挡关系或镜头运动，不要先增加装饰。如果结果变成普通桌面场景，回到用户提供的场景参考或克制的场景构图；只有用户提供或确认过场景时，才将其锁定为固定环境。如果进度没有对动作产生可见响应，简化动作并强化状态变化。保留成功产物，只重试失败部分。

## 步骤 6：质量检查

检查：

- 弹窗是物理化的叙事主体，而不是平面贴纸；
- 画面有可见纵深、遮挡和清楚的动作 → 弹窗反馈循环；
- 不依赖无依据的说明也能理解状态弧线；
- 用户提供的文字逐字准确；
- 累积、动作触发反馈、进度变化、中断、淡出和结算都有清楚时机；
- 重复弹窗保持视觉统一，按剧情顺序出现，并与空间发生一致的互动；
- 镜头运动没有破坏可读性；
- 结尾回应已建立的状态，没有无关尾屏；
- 音乐或音效没有暗示用户未要求的字幕；
- 静态图使用已选定的可用图像能力，并遵循其经过检查的约束；
- 交付的是用户要求的视频或静态图，不是假装可交互的原型。

## 能力边界

本 Skill 支持独立的 Windows XP 风格弹窗图和弹窗物理化的动作短视频。不生成可运行 UI 代码、交互原型、完整桌面复刻、通用现代模态框、无关桌面漫游、无依据的系统结论，也不精确复制参考视频。静态白底或隔离背景只用于弹窗资产；当用户提供场景时，不是最终视频的默认美学。长片、多条独立成片、复杂多片段剪辑或需要大量脚本 / 分镜审批的项目，应返回更完整的制作流程。
