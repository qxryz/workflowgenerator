# Blender 建模、执行与产物管理

按以下四个阶段执行。第 1 阶段的工程绑定和第 2 阶段的媒体输出隔离是制作前置条件，优先于建模 Reference、质量、速度和“直接放画布”的要求；未通过对应检查就停止后续制作或发布。每条约束在所属阶段定义，重试按第 3 阶段返回检查，不另起一套流程。

## 触发条件

用户要求使用 Blender 制作或修改、交付可编辑 blend，或续改当前 Blender 工程时适用。仅说“三维”“运镜”“白模”“动画”不足以在 Blender、导演台和生成式媒体之间选定 Blender。风格参考、素材来源、否定表达、概念问答或仅安装连接器的请求不触发制作。

## STEP 1: 连接并绑定本次作品

### 1.1 建立连接；断连时按状态恢复

先通过当前可用的 Blender 连接读取场景；成功即进入工程检查。失败时用宿主已有的应用或连接状态检查能力区分原因，不把所有错误都交给用户处理。不猜测连接设置或虚构恢复能力。

首次使用或缺少连接器时，有本地命令执行能力就使用本 skill 的连接器准备脚本 (`scripts/prepare-connector.mjs`)：先读帮助、检查状态，需要时安装并启用，再刷新当前对话的连接能力。脚本复用客户端登记的 Blender 社区连接器安装流程；用户已指定其他版本或已有可用连接时不擅自替换。安装所需的系统授权在客户端或系统界面完成，下载和授权等待不受下述 30 秒恢复周期限制。结果未知时先查状态，不重复发起安装；宿主不支持该入口时才使用可用的连接器界面，或告知用户具体缺口。安装成功不等于场景可读，不下载 Blender 应用本体，也不安装无关插件。

Windows 上，准备脚本会先诊断已确认的插件安装失败，再决定是否需要手动处理。对于明确支持的 Windows 依赖缺失，它会在已登记的连接器包内补齐，验证导入后重试安装一次；下载使用固定官方版本并校验完整性。不支持的运行时、与现有文件冲突或结果未知仍须明确报告，不改成全局安装 Python 依赖或任意下载。

本机应用发现使用 `scripts/blender-host.mjs`，支持 Windows、macOS 和经过核验的自定义安装路径。macOS 上先读帮助、检查状态、按需启动，再通过可信插件已有入口连接并真实读回场景；Windows 上使用下方合并了启动和连接的服务入口。两条路径均复用唯一运行实例，进程归属未知或多实例时拒绝新开。仅打开 Blender 不代表插件已启用或场景可读。

Windows 上完成连接器准备后，使用 `scripts/blender-service.mjs`：先读 `--help`，以 `--status` 检查，服务未连通时执行 `--start`。该入口会打开或复用 Blender、在本次应用会话启用已安装且身份匹配的插件、启动服务并真实读取场景。默认从当前 Design 对话取得已登记的包路径，也可用 `--package` 提供该核验路径；`--app` 指定已核验安装。命令时限留足 120000 ms。执行会短暂使用 Blender Python 控制台，应关闭阻挡对话框并避免同时输入；无需先单独运行打开应用的命令。macOS 沿用已有应用和插件控制入口。

准备结果中的 `startupSupported: false` 不禁用本 Skill 的 Windows 服务启动入口，也不是 Windows 无法自动启动插件的证据。脚本不切换、保存或重置工程，不全局保存偏好设置。多实例、插件身份不符、应用忙碌或派发结果未知时，检查具体阻碍，不盲目重装或重放。辅助程序成功后，仍须通过当前对话再次读取场景，再开始制作。

| 实际状态 | 允许的恢复动作 |
|---|---|
| Blender 未运行且已安装 | 告知后主动打开已安装应用，不要求用户先手动打开；不通过已断开的 Blender 内部工具启动自己 |
| Blender 在运行，连接服务未启动 | 通过已有连接恢复入口或可用的本机界面，启动本任务已使用或由上述流程刚安装的可信插件服务，不切换其他插件或改写无关偏好 |
| 服务就绪，但场景读取失败 | 使用宿主已有的重连能力；不能用反复打开 Blender 或杀掉其他会话进程代替 |
| 工程正在切换或已知渲染仍在执行 | 给当前操作短暂就绪时间后再读状态，不因读取超时就重启或重跑制作脚本 |

一个恢复周期最多检查 3 轮、累计等待不超过 30 秒；这是避免恢复空转的停止条件，不是重启应用或中断渲染的时限。每轮据状态采取必要动作后再检查，保留进度和文件，不重复启动实例。成功以实际读回场景为准，不以窗口出现或服务就绪为准。

仅当上述动作不可用、权限不足、插件未受信任或有限恢复仍失败时，报告已检查状态、已尝试动作和需要用户完成的具体一步。连接器准备使用上述受支持安装流程；恢复已有连接时不擅自改端口、凭证、持久偏好或绕过权限。没有宿主恢复能力时要承认限制，不能声称已恢复。

用户明确要求重启时，先按 1.3 保护当前内容，再正常退出并确认原进程结束、重新打开、验证场景可读；无法确认未保存内容时先询问，不强杀。单纯发送打开应用请求不算重启。用户指定 Blender 就不因白模／运镜关键词或断连改用导演台；已走错路线时报告并停止该路线的后续制作，不影响其他任务。

### Blender 本体未安装时

连接失败或标准路径扫描为空，不等于 Blender 未安装。先检查应用所在主机、运行实例和已知自定义路径；位置仍不明确时，询问是否已经安装，必要时只请用户提供应用路径。无法检查仍属未知。已核验的安装直接复用，不建议重装。

确认缺少 Blender 后，说明当前缺的是桌面软件本体，给出 [Blender 官方下载页](https://www.blender.org/download/)，用用户的语言仅展示对应系统的步骤：

| 系统 | 用户安装步骤 |
|---|---|
| Windows | 选择与电脑处理器架构及连接器已说明的支持范围相符的稳定版本，运行官方安装器并按提示完成。若使用官方 ZIP 版，完整解压到持久目录，保留 `blender.exe` 的位置。参见 [Windows 安装说明](https://docs.blender.org/manual/en/latest/getting_started/installing/windows.html)。 |
| macOS | 选择支持实际 Mac 机型及系统的稳定版本，最新版不一定支持所有 Mac。打开 DMG，将 `Blender.app` 拖入“应用程序”，完成首次启动提示。参见 [macOS 安装说明](https://docs.blender.org/manual/en/latest/getting_started/installing/macos.html)。 |

不只说“去网上搜索安装”。提供官方入口、步骤和安装后的衔接方式。官网无法访问或兼容性未核实时如实说明，不编造下载地址或承诺支持。软件本体由用户安装并处理系统提示；本准备流程只安装连接器。

等待安装期间，保留需求、素材、目标作品和最近已验证步骤，暂停依赖它的启动与制作，不反复安装连接器。用户告知完成或新的检查发现应用后，重新核验路径与版本，准备或复用连接器，按上方对应平台的连接步骤读取真实场景。验证通过后接着原任务执行，不要求重复需求或再说“继续”；仍找不到时只请用户提供安装位置或具体安装错误。

### 有限的准备恢复

准备期间始终在当前对话保留原需求、素材路径、目标工程与最近验证的步骤。准备脚本已内置“确认包准备失败后复查状态，通过受管理安装器重试一次”；不会重试结果未知或授权失败。按帮助留足完整时限，不在脚本外再套重试循环，不删除冷却标记、不修改私有配置，也不从未登记来源下载替代包。

仍在安装时，最多在 30 秒内查状态 3 次，不发起第二次安装；仍忙则保留任务并说明准备尚未结束，不能误报安装失败。结果未知时先查状态再决定后续动作。包准备重复失败应定位客户端、网络或解压阶段，不直接让用户去设置页重复同一安装。没有受支持的恢复途径时，说明具体阻塞点及需要处理的最小一步。

准备成功后按本 skill 的应用连接步骤继续启动应用，真实读取工程、文档或场景，再自动接着原任务执行。不要求重复需求或回复“已打开”。无法确认未保存内容时不重启应用，不重放结果未知的创作写入。

### 1.2 确定作品归属

- 新对话默认新作品；明确继续、修改、打开或沿用某个可定位的已有作品时才绑定其 `.blend`。同一对话已绑定的作品直接续作，不每轮重建；明确另做新作品时重新绑定。
- 连接后读回工程绝对路径、未保存状态、场景及对象归属，例如 `bpy.data.filepath`、`bpy.data.is_dirty`；未命名也须记录。文件名、Collection 名或同一个 Design 目录都不是复用授权；继续目标不明确时请用户选择。
- 在对话中维护目标工程路径、已有作品标识、旧工程恢复路径和当前阶段；辅助脚本生成的场景标识应与其返回记录核对，不依赖平台字段名识别作品。不创建额外画布说明节点。已有混合作品时先确认恢复方案，不擅自拆分或删除。

### 1.3 核验保存并告知切换

- 无需切换时继续当前绑定作品，不为正常编辑反复询问。需要切换时，已保存且无未保存修改的旧工程也要确认文件真实存在；不能仅凭 `is_dirty=False` 断言可恢复。
- 有未保存修改、未命名或恢复证据不足时，先在已授权的持久位置保存，或另存唯一、不覆盖的恢复副本；用另存副本方式（如 `save_as_mainfile(copy=True)`）时不把副本误称为已更新原文件。确认保存调用成功、文件存在和必要依赖后再切换；位置/权限不明或保存失败时停止并询问。
- **切换前必须告知旧作品名、保存状态、完整恢复路径和新目标路径。** 区分“原本已保存，本次无需重存”“本次已保存”“已另存恢复副本”；只有实际完成后才这样报告。用“切换出旧工程、保留原文件”，不要把切换文件说成取消旧对话任务。

### 1.4 准备独立文件，再切换和复核

新建、切换、建模分开执行，不放进同一段长脚本。新作品优先使用配套空工程生成脚本 (`scripts/create_clean_work.py`)：在**独立后台进程**中运行已安装的同版本 Blender，生成唯一目标文件，然后由当前连接的实例正常打开。脚本拒绝前台执行、载入用户工程和覆盖已有目标，不承担连接服务启动。

```text
<Blender 可执行文件> --background --factory-startup --disable-autoexec --python-exit-code 1 --python <Skill目录>/scripts/create_clean_work.py -- --output <本次作品目录>/scene.blend --name <作品名>
```

参数须替换为实际绝对路径并按宿主正确引用。生成成功后记录脚本输出中的路径、场景和作品标识；失败时检查实际文件和错误，不覆盖不确定的半成品，也不退回重置当前实例。没有后台执行能力时，仅使用已验证不含旧作品的干净模板；无安全来源就报告阻碍。

继续已有作品则复用定位好的文件，跳过生成。切换前先核对该文件存在，再通过 `bpy.ops.wm.open_mainfile(filepath=目标路径, load_ui=False, use_scripts=False)` 正常打开；不要在用户当前实例调用 `read_factory_settings`、重置偏好或关闭软件来实现新建。新建集合、隐藏旧模型、向旧场景追加后另存也不算独立工程。

打开后单独读回路径、场景、对象和作品标识；新空工程应无旧对象，续作工程应匹配预期作品。若响应断开，先按 1.1 恢复并读回状态，不盲目重复打开或重新生成文件。确认后再告知“已切换到……”并开始制作。

**通过条件：旧内容有可恢复文件且用户已获知位置，目标文件已正确打开，切换后仍能读取场景且作品身份匹配。**

## STEP 2: 确定交付类型与输出位置

### 2.1 区分源工程、过程文件与交付文件

确认当前 Design 创作项目的真实目录，不把 Hub 源码目录当成创作项目。完成制作或修改时，默认交付可编辑 `.blend`，并将渲染好的预览回传画布；无需用户另行要求渲染或放到画布。用户明确要求不渲染或不上画布时遵从。按本次任务的目标产物判断静态或动态，不凭已有工程中无关的动画数据判断。

| 目标产物 | 默认画布预览 |
|---|---|
| 静态模型、白模、场景或单幅构图 | 一张展示成品的渲染图，如 PNG 或 JPEG |
| 动画、运镜或随时间变化的模拟结果 | 一条覆盖目标运动范围、渲染完成且可播放的视频；优先使用受支持编码的 MP4 |

不为静态建模任务额外添加动画。动态产物不得用单帧、拼图、视口录屏或帧序列目录代替渲染视频。最终预览与可编辑源工程必须对应同一已保存版本。用户要求的最终图片或视频直接作为预览，不重复渲染或发布。用户明确要求多个交付物时按其数量交付，否则不默认增加最终预览数量。

| 类型 | 保存与展示方式 |
|---|---|
| 可编辑源工程 | 保存到第 1 阶段绑定的作品路径，保留必要依赖；不属于禁止交付的中间帧 |
| 批量渲染帧、未选中的过程自检预览、缓存、临时音轨及所有待验收图片和视频 | 在系统临时目录中建立唯一任务目录，渲染、合成和验证均留在项目外；不自动或主动收录到画布 |
| 选定的关键阶段预览、最终画布预览及用户要求的媒体或导出模型 | 验证后再发布到指定位置；不将未验收媒体提前输出到项目扫描目录 |

- 解析并确认过程目录的真实路径不在 Hub 创作项目资产扫描范围内，不复用其他任务的固定目录。不凭 `frames/`、`renders/` 等名称或新写入的 `.hilo/asset-ignore` 假定安全，不改已有排除配置，也不用可能在启动时被清理的 `.hilo/.tmp/` 存续跑数据。
- 在造型完成、材质／灯光完成等有意义的视觉检查点，阶段自检通过后，自动将一张有代表性的渲染图回传画布，标为“过程预览·阶段名称”，与最终成品区分；无需用户另行要求。不为每个对象检查或每次迭代发布图片。用户明确要求不展示过程预览或不上画布时遵从。
- 批量帧、缓存、未选中的自检预览及待验收媒体仍在隔离目录。交付整套帧序列须明确交付形式，不铺满画布。先写入项目再移动、隐藏或分组帧图都不算隔离。

### 2.2 核验实际输出设置

- 静态预览未指定视角时，选择能展示成品的代表性相机构图。读回活动相机、渲染帧、尺寸、图片格式和隔离目录中的绝对输出路径。渲染作品本身，不以应用窗口截图替代。
- 视频渲染前读回活动相机、尺寸、输出类型、隔离目录中的绝对路径、完整目标帧范围和帧率，并确定合成目标。PNG/EXR 等帧序列必须使用隔离目录中的帧前缀，再单独合成为视频；设置 H.264 或把路径写成 `.mp4` 不能代替正确的输出类型。
- **回传 Design 画布的视频预览**：默认使用 24 或 30 fps，并在发布前核验渲染文件的实际平均帧率。如果预览要作为 MiniMax H3 参考素材，实际平均帧率必须在 23.5–60.5 fps 之间；可播放的 20 fps 文件不兼容 H3，必须留在隔离目录，直到兼容的渲染或转换通过。
- 待验收合成只使用能明确写入隔离目录且不会自动发布的本地媒体处理能力。若某种处理方式会自动把输出发布到画布，则不用于待验收合成；缺少适合的本机合成能力时说明阻碍，不绕过隔离。

**通过条件：输出类型与真实路径匹配，过程文件不会被扫描或自动发布。检查通过后才能生成预览文件、渲染或合成，无需额外等待用户确认。静态建模只需隔离渲染单张图；后续增加动态内容时，先补齐视频设置。**

## STEP 3: 在已绑定工程中制作与检查

### 3.1 按需选择建模方式

- 建模或修改形体前读建模知识参考 (`references/modeling-knowledge.md`) 的“方法选择”和“几何约束”，再按任务读取操作章节及验收项。可直接使用，不要求下载示例或打开官方工程；仅运镜、渲染已有场景时跳过建模细节。
- 从文字、草图或参考图提取主结构、尺寸与单位、截面、厚度、连接、对称及重复关系，为每个主结构选择方法；单图未知的背面或内部结构记为假设，不伪造精确尺寸。
- 连续曲线、弧形、拱形、圆角、弯曲墙体和流线型外壳采用适合的曲线、放样、连续网格或修改器，不默认用多个立方体拼接。白模可简化细节，但保留决定轮廓和空间识别度的连续性；真实的砖块、板材、装配零件仍可独立建模。

### 3.2 分阶段制作与自检

- 仅操作已绑定作品。先建立可调主轮廓，再补厚度、开孔、圆角和细节；保留曲线、截面及修改器等可编辑来源，转换或应用前保留恢复来源。
- 每完成一个主结构，读取实际几何状态，并用视口或低成本预览检查轮廓、比例、连续性、穿插和相机可见性。尺寸基于世界空间评价后几何；按展示、动画、打印或导出用途核验，不照搬样例高面数或节点设置。
- 按第 2 阶段在隔离目录生成和检查预览。到达有意义的视觉检查点后，确认选定图片可解码、能清楚展示当前阶段，再按 4.2 回传画布，然后进入耗时的最终渲染；不等最终视频完成才展示进展。Agent 自检通过后继续，用户要求阶段确认时才等待。随后渲染最终静态图，或渲染完整目标动画并在隔离目录合成为视频。过程预览不能替代最终交付物。

### 3.3 失败与续跑

- 连接错误只进入 1.1 恢复；恢复后按 1.2、1.4 读回作品和实际执行结果，再续跑。脚本报错或超时不代表之前操作已回滚，不整段重放初始化或追加对象。
- 代码/API 错误则在连接正常时读取当前版本可用能力及已完成阶段，仅修复本任务缺失部分；几何问题按 Reference 定位，不静默退化为方块堆砌。改输出格式、引擎或路径后重新通过第 2 阶段，不能把兼容性重试变成工程重置或把帧输出到项目。
- 已确认进度可继续时自动续作，无需反复等待用户说“继续”；仍无法安全前进时说明阻碍和恢复位置，保留源工程与过程文件。

## STEP 4: 验证产物后发布

### 4.1 按交付类型验证

- **源工程**：保存本次作品的可编辑 `.blend`，用户要求导出时另存指定格式；核验文件存在、保存状态、主要对象和依赖，提供路径与实际限制。预览与源工程一并交付，不能相互替代。
- **静态产物**：确认真实图片可解码、尺寸符合目标，并检查成品构图、照明和材质是否清晰可读。选择一张最终图回传画布。
- **动态产物**：等待完整目标范围渲染及必要的视频合成结束。确认真实视频可解码、可播放，核验尺寸、时长与帧范围及帧率的对应关系，以及必要音轨；检查首、中、尾代表帧中的主体或相机运动，排查缺帧和黑帧。回传渲染完成的视频，不以缩略图或未完成的预览片段替代。
- **回传画布的视频预览**：将最终文件的实际平均帧率作为交付门槛。作为 H3 参考素材时，只接受 23.5–60.5 fps；可播放的 20 fps 文件仍不通过，必须重新渲染或转换后再发布。
- 命令成功、`VIDEO_RENDER_COMPLETE` 或文件名后缀都不是验收证据；`*.mp4####.png` 仍是帧序列，返回隔离合成，不登记不存在的 MP4。修改作品后同步更新并重新验证预览，确保与交付的 `.blend` 一致。

### 4.2 发布已验证文件

- 验证通过后，将选定的阶段预览或最终预览复制或导入到指定的持久交付位置，再通过当前可用的媒体导入或展示能力回传当前 Design 画布。节点必须引用已验证的真实文件，图片和视频类型正确；已发布节点不能依赖临时渲染文件。
- 确认画布已展示图片或已提供可播放的视频。仅给文件路径或聊天附件不算确认画布交付。自动收录已创建节点时复用。同一阶段的修改复用或更新原节点，不每轮新增，过程标识与最终成品保持区分。不重复发布同一媒体，也不额外添加视频缩略图节点。发布结果不明时先查已有节点再重试，不为登记已有的已验证媒体重新渲染。
- 渲染、验收或画布回传失败时，修复失败步骤或说明具体未完成环节，保留源工程和续跑文件。区分“已渲染”与“已回传画布”，不能仅凭保存了 `.blend`、生成了帧序列或未确认的发布声称完成。未经用户确认清理范围，不删除已有节点、资产、源工程或续跑文件。

**完成条件：可编辑源工程已验证、交付位置已确认，静态产物的一张渲染图或动态产物的一条可播放渲染视频已回传画布；用户明确免除预览或画布展示时遵从。只报告实际完成的结果。**
