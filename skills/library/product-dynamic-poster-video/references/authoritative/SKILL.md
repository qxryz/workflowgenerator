# 万物海报与视频

这是一个严格的线性创作流程。权威系统提示词和光影预设不得改写、概括、翻译、裁剪、重排或“优化”。

## 启动

1. 读取 `workflow.yaml`，按其中的阶段顺序和闸门执行。
2. 执行 `python3 scripts/verify_integrity.py`。任何哈希失败都必须停止，明确报告资源已被修改，不得使用近似提示词继续。
3. 收集产品原图和工作流列出的必要意图；用户没有指定的非必要项按 `workflow.yaml` 默认值处理，不重复追问。

## 严格执行规则

- 第二阶段必须逐字读取 `prompts/poster-system-prompt.txt`，将其完整内容作为系统指令，并将产品图作为图像输入。补充需求只能作为独立的用户输入附加，不能插入或改写系统提示词。
- 第二阶段只接受一个裸 JSON 对象。用 `python3 scripts/validate_poster_json.py <输出文件>` 校验；失败则要求模型在不改变创意意图的前提下只修复结构。
- 第三阶段将原始产品图与第二阶段通过校验的完整 JSON 一起交给图片模型，生成一张主海报。不得用文字描述代替原图。
- 第四阶段以主海报为唯一母版，分别逐字读取并提交以下四个 JSON 提示词，每次只用一个预设，生成四张独立图片：
  - `presets/edge-light.json`
  - `presets/side-key-light.json`
  - `presets/overhead-key-light.json`
  - `presets/low-angle-key-light.json`
- 第五阶段必须逐字读取 `prompts/video-system-prompt.txt`，将其完整内容作为系统指令，并同时提供第四阶段的四张光影参考图。只接受该提示词规定格式的成片提示词。
- 第六阶段把四张光影参考图和第五阶段的完整提示词一起交给视频模型，生成 15 秒视频。
- 每个阶段的输出只流向下一个阶段。上游校验未通过时，不得跳步或用临时内容替代。

## 忠实性边界

- 两段 `.txt` 与四个 `.json` 是来自飞书源文档的逐字资产，`source-manifest.json` 记录来源、版本和 SHA-256。
- `workflow.yaml` 只描述编排，不取代系统提示词。
- `schemas/poster-output.schema.json` 与校验脚本只检查输出，不改变系统提示词。
- 源海报提示词同时写有“values 恰好 12 个字段”和一个含 13 个命名字段的结构示例。不得私自改原文；本 Skill 以明确列出的 13 个字段为机器校验依据，并在校验报告中提示这项源文档矛盾。

## 交付

返回主海报、四张按光位命名的参考图、最终 15 秒视频，以及第二、第五阶段的原始文本输出。若运行环境暂不支持某个媒体模型，保留已完成产物并明确停在哪个阶段。
