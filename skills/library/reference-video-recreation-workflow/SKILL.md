# 参考视频复刻：导演、制作决策与验收

## 开场问询：先收集原片与修改要求

每个新的复刻任务，先用一次简短问询收集：

> 请上传你想复刻的视频，并描述需要修改的部分。如果要替换人物、产品、标志或其他主体，请一并上传对应参考图或素材。没有特别说明的部分，默认沿用原片。

按已有信息补问，不机械重复：
- 没有原片和修改要求时，同时询问这两项。
- 已经上传原片时，只询问需要修改什么，不要求重复上传。
- 修改目标明确但缺少必要替换素材时，只补问缺少的素材。
- 原片、修改要求和必要参考都齐全时，直接进入证据分析和变更脚本，不重复开场问询。只有原片而没有修改范围，不算完成开场收集。
- 只有用户明确回复“按原样复刻”或同等含义，才把它视为无改动范围。如果用户只上传原片并说“复刻这个”，没有说明改什么，必须先询问修改内容，不得直接推断为原样复刻、分析或起草脚本。
- 画幅、节奏、声音及其他未修改属性默认继承原片；只有真实冲突或缺失输入阻碍执行时才追问。
- 开场问询只收集需求，不等于生成授权；生成前仍须经过脚本确认门槛。

把参考片重建为 MiniMax Design 项目中的可追溯创作流程：参考证据 → 用户可读变更脚本 → 明确确认脚本 → 平台视频生成 → 对照及经授权修正 → 视频与用户要求且实际支持的可编辑交付。默认在平台现有项目、画布、模型和插件内完成；保留用户指定的工具、精度、预算和交付要求。

本技能是平台工作流指令，不自带 API、模型或编辑器能力。调用运行环境实际提供的工具；指南中的产品功能不等于当前会话已连接的工具。文档依据与未确认能力见 [平台适配依据](references/platform-guide.md)，判断功能边界或更新适配时读取。

每次规划或提交视频任务前，读取 references 中对应的操作参考，并核对 MiniMax Design 当前可用能力。历史文档不等于当前能力保证；批准的视频能力不可用时说明缺口，不静默切换。静态图片及独立音频仍使用平台相应能力，不能从视频操作参考推断它可独立输出这些素材。

## 0. 主控职责与积分保护硬规则

主控智能体承担“复刻导演＋制作决策者＋验收负责人”，不只是拆镜头和转发生成任务。职责扩大不等于消费权限扩大。

- **复刻导演**：拆解信息顺序、视觉层级、动作触发与停顿、转场连接、声音与节奏；每个关键段落写明最不能丢的观看效果。区分观察、推断和未知，不把推断冒充创作者意图。默认忠实复刻，创意改编和品牌替换以用户要求为准。
- **制作决策者**：为每镜选择编辑器重建、视频生成或混合制作，并说明理由、共用素材、可编辑范围、风险与节约方案。默认使用平台参考复刻：原片负责运动、时序和布局，替换素材负责主体身份，指令负责文案和主题改动。编辑器只作为按需后期或修复路线，不是默认重建流程；缺失能力如实说明，不自行降低硬性交付标准。
- **验收负责人**：基于参考和实际结果定位问题，区分硬约束失败、影响观看的问题与可接受近似；提出最小修复及其相邻镜头影响，不自行批准新消费，不用虚构相似度分数代替证据。

**最高优先级硬规则：验收不通过，不得直接重新生成视频。先诊断、优先利用现有素材修复；任何视频重生成、视频生成式编辑、延长、换模型重做、补生成替代镜头或额外候选，都必须先获得用户针对本轮的明确授权。**

- 首次制作授权、总体预算、尚有积分、系统建议重试，以及“优化一下”“不太像”“继续”等模糊反馈，都不等于重生成授权。
- 仅在前文唯一待确认事项已明确列出镜头、数量与单轮范围时，用户的“确认重生成”或语义明确的同意才可授权。记录具体镜头、每镜生成次数、时长、改动与允许消费范围；默认只执行明确批准的一轮，不设自动重生成额度。
- 用户批准一次后仍不通过，必须再次停下诊断并征求新的授权。不能以技术重试、样片、局部修复、自动优化或补镜头之名绕过此规则。
- 任务报错、无结果或超时同样不授权新一轮提交；先核实已有任务和产物，再询问是否重试。未知状态不重复提交。若无法核实计费或底层重试行为，明确说明未知，不承诺绝无扣费。
- 修复方案优先级：复用已有候选或可用区间 → 调整剪辑、裁切、文字层、声音同步和已支持的动效 → 经用户接受的近似或降级 → 用户单独授权的最小范围重生成。影响创意、规格或可编辑性的修改仍需确认。
- 不将后期、分析、渲染或图片生成一概称为免费。已授权、确认不增加生成积分且不改变硬约束的后期修复可继续；任何新增付费步骤、费用不明的执行或超出原授权的制作先告知并确认。
- 有实际报价时提供依据和金额；没有时说明“预计会消耗额外积分，具体数量暂无法核实”，不得编造价格或保证修复成功。没有回复即不执行重生成。

## 1. 输入与能力检查

接收对话附件、本地文件、画布节点、主体库引用或网页链接。主体库是当前界面名称，旧资料中的资产中心指同一实体库。用户指定参考后先读取该对象；不要搜索其他项目来替代参考。链接必须实际能播放完整视频，仅有网页、封面或截图不够。无法取得全片时请用户上传原视频或完整录屏，可继续检查工具，但不要编造镜头。

记录参考的时长、分辨率、画幅、帧率、音轨，明确逐镜复刻还是允许创意改编；默认为逐镜复刻。品牌或文案替换按用户要求执行。用户未要求替换时保留参考规格。

只核实本次交付真正需要的能力，并用项目文本节点标记“可用 / 不可用 / 未验证”和证据：

- 读取参考视频及本任务需要的画面或时间点。
- 创建或更新本次实际需要的媒体、文字、分镜表、时间线或平台项目素材。
- 当前启用的视频、图片或音频能力、输入输出限制，以及可核实时的计费信息。
- 只有用户要求或修复方案依赖时，才核实多轨、文字、裁切、转场、效果、关键帧、缓动、遮罩、嵌套、保存和导出。
- MiniMax Design 项目保存及实际提供的保存/导出能力；必须核验素材和已支持的可编辑属性是否保留，不能预设结果。

优先使用平台现有工具及已启用插件；需要手动操作时依据当前界面，不臆造工具名、参数或项目文件格式。没有平台连接时可整理分镜、提示词与适配材料，不能声称已创建平台节点或完成原生工程。

## 2. 确定执行路径

默认路线是平台参考复刻，包含文字密集界面及动态图形。原视频负责运动、场面调度、事件顺序、时序和声音参考；替换图片负责主体与设计；提示词明确文案和主题替换。不能因为原片含精确动效或文字，就默认改成编辑器重建、要求提供可编辑原工程或强制先单独生成静态标识。

只有第 3A 节完整变更脚本已获用户明确确认、参考满足当前限制、执行范围与消费决策已明确时，才生成一条完整首版，不额外拆成不必要的样片。笼统的“复刻”或“全部换成某主题”不等于批准尚未展示的脚本。用户要求风格转译时，可让已有替换图片在视频生成中完成对应风格变化。如输入限制需要裁切、转码或分段，解释真实兼容问题并保留用户的创作约束；涉及有意义的内容改变时先征求同意。不重复询问已经确认的生成路线。

精确运动是验收目标，不是生成前保证逐帧一致。先核对证据、绑定参考，再验收实际结果。用户专门要求样片或已批准方案需要样片时，确认样片范围和费用再做；样片或完整首版未通过均进入诊断与用户决策，绝不自动重生成。

若任务明确要求“所有动画在平台内制作、独立场景合成、主合成、可编辑文字和关键帧”，这些是硬性交付条件。平台运行时缺少其中任一能力时，明确缺项并继续不依赖它的分析与素材准备。不以不支持的能力或生成视频冒充这些交付物；不把画布分组视作独立动效合成。

默认走全能参考生成，除非用户明确要求平台内可编辑图层，或存在阻止生成的硬能力缺口。生成片段只有片段级可编辑性，不具备其内部物体、字体和运动的独立图层。确需平台内剪辑步骤时说明原因；改变交付方式须先征得同意。

本技能仅使用 MiniMax Design 内实际提供的平台能力；不引入其他平台或外部生成服务。

视频模型的选择不自动取消平台内可编辑图层、独立合成或动画制作要求；生成视频不等于分层可编辑工程。

### 制作决策与共用视觉规则

从参考片提炼主体身份、构图与排版层级、场景材质、运动方向、停顿与转场习惯，作为跨镜头共用规则；用户的硬要求优先。参考颜色通过素材传递，精确色值只采用可靠测量或用户规范，不从语义描述编造。

若更换品牌或产品，区分可迁移的视觉方法与必须替换的原品牌身份。每镜记录：关键观看效果、不可改变项、制作方式及理由、共享参考、未知能力和最低成本备选方案。文字精确、层级可编辑等硬要求不能因视频生成较快而取消。

## 3. 在画布组织参考与分镜

复用用户指定项目或为本任务创建独立项目/画布，不覆盖其他创作。推荐按“参考、分镜、场景素材、剪辑、验收”分组；场景命名为 S01、S02 等，候选与选定版本分别标记。分组用于组织素材，时间先后由剪辑时间线决定。

创建分镜表节点，并将关键画面挂接至对应场景。表格字段为本技能约定，不是平台 API 字段：

| 字段 | 内容 |
| --- | --- |
| scene_id | 稳定场景标识 |
| time_range | 起止时间及起止帧，结束帧不包含 |
| reference | 参考视频、关键截图和时间点 |
| visual_spec | 精确文案、换行、布局、字体、颜色和层次 |
| motion_spec | 动作、停顿、缓动、转场重叠和音画同步点 |
| assets | 输入引用、生成结果与选定版本 |
| route | 编辑器重建 / 经允许的视频生成 / 混合，以及选择理由 |
| key_effect | 本镜最不能丢的观看效果与不可改变项 |
| shared_rules | 共用主体、视觉规则及参考用途 |
| acceptance | 约定的硬约束、验收重点和允许近似 |
| approval | 当前制作授权范围及尚待确认的新增消费 |
| status | 待制作、生成中、待验收、待用户决策、选定、已剪辑、受阻 |

检查场景首帧、稳定状态、动作中段和末帧，在转场附近加密观察。测量位置、尺寸、边距、裁切与遮挡；记录字重、字号、字距、行距、锚点、颜色、阴影、模糊和纹理。字体不能确认时标注候选与替代，不宣称精确匹配。

统一时间线帧率；变帧率源按时间戳对齐。动作规格记录位置/缩放/旋转/不透明度的关键状态，依据中间状态拟合缓动，区分观察、估计与未知。先锁定结构与大动作，再处理细节。

## 3A. 必经步骤：用户可读变更脚本与确认门槛

首次生成视频前，以及变更后重新生成前，必须先在画布创建或更新一份可阅读、可编辑的《复刻变更脚本》。它是最终画面内容的唯一依据，不是宽泛创意简报，也不只是长提示词。默认仍用平台视频生成；此步骤不要求编辑器重建或另行生成图片。

文档必须包含：
1. **范围与版本**：原片、替换素材、输出范围、改什么与不改什么、版本号和状态：草稿、待确认、已确认、需修订。
2. **逐镜脚本**：可见起始状态、事件顺序、关键运动与转场衔接、结束状态和声音意图。沿用的运动由原片提供证据，不伪造精确时间戳或关键帧；默认以原片可观察的事件顺序和相对时序为依据，估计时间明确标注。
3. **文字替换表**：对关键文字记录稳定编号、场景/出现窗口、唯一位置、保留/替换/删除、逐字最终文案、大小写、标点、换行、出现/推进规则及核准状态。背景界面文字只记录载体区域和视觉处理，不强制穷举转录。只有文字作用与创作目标相关时，才把小标签、文件名、评论、数字或转场短字列为逐字项目。
4. **元素变更表**：逐项列明主体、图片、标志、图标、背景和主题部件的替换或保留，注明来源、最终外观、作用范围及运动/布局不变量。不得悄悄更换无关图片、增减节点或把主角身份套给配角。

**文字作用与精度分级：**先判断文字在本次创作中的作用，再决定核对和提示词精度。品牌名、关键标题、剧情信息、用户指定文案，以及会影响创作目标的文字，属于**关键文字**：必须锁定完整字符串、大小写、标点、换行、显示状态和推进过程。录屏中非重点的账号、评论、互动数字、音乐标签等，默认属于**背景界面文字**：保留其载体区域、位置、层级、视觉密度、图标关系和滚动方式，不逐条转录，不因小字难辨阻塞生成。保留界面不等于逐字复刻全部界面字符。如果评论、账号或数字承载剧情信息，或用户明确要求精确还原，则升级为关键文字。由主控判断分类；只有文字作用会实质影响创作目标且仍有歧义时才向用户提问。
5. **待核对与确认区**：无法定位的载体、不可辨认的文字、数量不明、未定稿文案、缺失素材及需用户选择的改动；记录用户批准的具体文档版本与执行范围。

可执行脚本禁止出现词库、多个备选、“等等”、未填占位符、“其余标签换成相关词语”或让模型自选文案。每个保留的文字载体必须有明确的保留/替换/删除决定。原文字看不清时，可以用唯一定位的截图/位置加上用户确认的完整新文案解决，不必猜旧文；若载体本身、数量或新内容仍不明确，该项标为阻塞，不提交相关生成。可以展示草稿，但不能将其称为已就绪或已批准。

打字和文字动效需要明确完整文案及必要的阶段显示内容。把原片的显示窗口和运动与被替换字形分开：保留文字位置、层级和动画，不保留旧词或旧字形。新文案放不下时提出明确的改稿或版式供确认，不能在提交时自行缩写、改写、翻译、重复文字或改换行。

展示实际脚本版本时一并说明本轮生成范围及相关费用信息，只通过普通对话确认一次。在正在进行的视频创作任务中，用户确认脚本即授权按已说明范围生成一轮，不再追加“是否生成视频”的二次确认。内容与工具关键检查通过后直接执行。首次制作和失败后明确审阅的修订脚本均遵循此规则。用户明确只审脚本或暂不生成时例外，必须尊重。

一并记录批准版本、模型、参考素材、时长、数量与消费范围；费用未知如实说明，不以此反复弹出同一授权问题。一次授权执行后即已使用，不包含后续自动重试。验收失败仍须新的用户决定；确认已展示的修复/修订脚本就可以构成该决定，不再另问重复授权。改变已确认内容、范围、模型或费用时，仅确认真实变更。之前的成片确认、模型选择、沉默或无关/旧版本批准不能代替新脚本确认。技术核对由主控完成；确有阻塞要说明具体原因，不能谎称用户尚未授权生成。

提交前逐项核对已确认文档与执行提示词：文字和元素编号全部覆盖，最终文案逐字复制，参考与职责匹配，无未授权改动、无未解决项。以用户当前文档修改为准，不拿旧稿或头脑风暴版本提交。所有最终文案都明确写入生成指令，不能仅给模型一个画布文档文件名。

### 原片时序锁定与提示词编译边界

当用户要求保留原片运动、节奏或时序时，原视频对事件顺序、显示窗口、停顿、重叠、转场和音画同步关系拥有时序权威。变更脚本只决定什么要替换、什么要保留，不能被重新编成一份自创的剪辑时间表。

- 默认用原片事件定位：如“开头看板段”“原片口号转场”“照片落位后”“原片结尾”。不能为了组织提示词而平均分段或自行分配新的秒数。
- 未经源视频核实的时间只能作为查找线索，不能变成生成指令；无法核实时直接省略。场景编号不代表新增切镜。
- 编译提示词可以展开已批准的视觉和文字改动，但不得加入未经批准的运镜、材质、动作节拍、转场或时序，也不得把已批准的像素主体擅自扩写成软胶或写实主体。
- 如果已批准文案无法适配原显示窗口，必须提出具体文案或版式修改供用户确认；不能自行延长、压缩、延后或重排原片事件。
- 提交前检查每个数字时间段和每个新增运动描述：必须有原片证据或用户明确批准。没有依据就删除，不要生成后再解释。


生成后对照同一批准版本逐项验收：关键文字执行逐字检查，包括过渡帧及短暂旧字残留；背景界面文字检查载体位置、层级、密度、图标关系和滚动，不把非重点字符差异直接作为主要失败。区分脚本含糊与模型渲染失败；明确文案降低歧义但不保证模型绝不出错。第 0 节重生成须单独授权的规则始终有效。如果证据相互矛盾，具体可见的反例优先于概括性语义总结。抽样画面只能代表抽样范围，不能据此宣称逐帧通过。没有实际听到或独立核实音频时，声音只能标为未知，不能判定通过。

## 4. 生成与复用平台素材

先复用本任务已提供的品牌、产品、角色和背景资产；通过节点引用或对话中的资产引用建立关系，避免仅在提示词里写文件名。平台支持时自动连线和分组，保留源素材、提示词节点、结果节点与场景之间的关系。

视频模型默认使用 MiniMax H3。用户明确指定其他模型时，先核验其当前参考、时长、格式与声音能力，再遵循用户选择；经过一次已授权的针对性修正仍失败时，切换其他兼容模型，不与同一模型反复死磕。图片和独立音频只在用户启用的能力范围内选择。若用户启用 Ask 模式，按该模式交互；不擅自扩大模型范围。实际版本、尺寸、时长和价格读取当前界面或能力信息，历史操作参考只用于提交前校验，发现冲突先核对入口与版本，不从历史促销写死费用。

- 照片、插画、背景、纹理：使用平台可用图像生成或编辑能力，提示词明确主体位置、构图、画幅、留白、色彩和所需透明背景。
- 文字、标识、几何形状：保留准确文案和结构；优先使用可编辑文本/形状，生成图片中偶然出现的文字不能替代需要编辑的文字层。画布文本节点也不自动等于时间线文字层。
- 视频：仅在允许的路径使用，并先核实模型支持的首尾帧、多参考、音频和时长条件。不能假设每个模型都支持同样控制。
- 视频提交：使用“参考素材说明、核心创意、画面过程说明”三段提示词；将每个实际引用及用途对应清楚。按当前 MiniMax Design 入口校验时长、参考数量、格式及其他限制，不向工具传未经确认的参数。
- 声音：保留用户提供且属于任务范围的音轨，或使用平台可用能力制作配音、音乐和音效；缺失时报告，不把静音版本描述为完整音画复刻。
- 只有 MiniMax Design 内实际提供且本任务确实需要的辅助能力才可采用；不安装或引入外部平台依赖。

检查每项结果是否符合构图、尺寸、透明通道和风格要求，为后续平移与缩放预留边缘。预算优先用于代表性场景和失败项的修正，不无差别批量生成。需要复用的选定素材可在实际支持保存时按名称和分类保存到主体库。

## 5. 异步任务、版本与恢复

生成提交后记录平台返回的任务标识、输入引用、模型和参数、目标场景、结果节点及状态；没有返回某字段时留空并说明，不编造 ID。批次规模遵循实际并发限制与预算。

MiniMax Design 指南说明停止 Agent 回复后，生成任务仍可能继续并回到画布。因此恢复会话、取消回复或遇到超时后，先检查已有任务状态及画布结果，再决定是否重试。状态未知不等于失败，停止回复不等于取消生成；不要重复提交同一批次造成额外费用。

已确认失败也不能自动重试视频任务；先记录原因、现有产物和可能新增费用，按第 0 节取得本轮明确授权。保留失败原因和旧版本。用户修改画布后先读取最新节点及引用，沿用已选版本，不能把旧候选覆盖回去。新增结果须通过验收才进入剪辑。

## 6. 剪辑与动效工程

仅在需要拼装、确定性后期、用户同意的修复，或用户明确要求对比交付时使用实际可用剪辑能力；对比视频不是默认制作或验收交付物。不把建立额外编辑工程作为默认平台视频生成前置条件。相关操作按镜头范围统一尺寸、帧率、音频同步与转场重叠。使用正常速度预览动作和节奏。

历史操作参考中的帧率与声音说明仅作核对线索。主时间线保留用户约定帧率，用时间戳对齐和实际支持的重采样处理差异，不能直接重新解释帧率造成加速/减速。短于 4 秒的目标镜头可生成至少 4 秒后裁切，关键动作需落在保留区间；长于 15 秒的镜头分段并验收衔接，不通过随意变速凑时长。合成前检查每段生成音轨，避免与主配乐重复叠加；纯静音交付须显式静音并验证。

若已验证支持嵌套合成，为每场景建立独立合成并汇入主合成；保持局部时间和主时间映射正确。若只有多轨时间线，按场景区段及命名轨道组织素材，并准确说明与独立合成的区别；硬性要求未满足时不能按完全完成交付。

先匹配静态关键画面，再设置关键帧、缓动、错峰、遮罩、过渡和细节。仅使用已验证支持的动画属性。参考原片留在对照区域，不作为整段输出冒充重新制作。

保存版本及所需素材依赖。仅使用 MiniMax Design 实际提供的保存或导出操作，绝不手写未经支持的工程格式。保存或导出后核验素材、文字、轨道、转场、关键帧和嵌套是否保留；不支持的属性如实说明。

## 7. 对照与局部修正

把预览与参考按时间戳、尺寸及色彩解释对齐，以并排图/叠加图辅助静态检查，并完整观看时间线检查运动；无法执行某种比较时如实记录。

在验收文本或表格中记录场景、时间点、观察差异、修正措施、复查结果。优先修复镜头遗漏和时间错位，再处理布局/文字、字体/色彩、轨迹/缓动、转场及小细节。默认切点误差目标为一帧以内；能力或参考精度不允许时报告实际差距。不可凭印象给出相似度百分比。

验收不通过即转为“待用户决策”，不得把验收结果当作视频重生成指令。先给出简短诊断：镜头与时间点、观察差异、严重程度、可能原因及置信边界、现有素材能否修复、最低成本方案、对相邻镜头的影响。原因不确定时提出待验证假设。

向用户提供与本次问题相关的选择：保留现版并标明差异、仅用现有素材后期修复、暂停补充素材、或授权指定镜头重生成一轮。只列实际可执行的选项，不能默认选择重生成。用户仅要求优化时，先澄清优化方案，不默认增加模型调用。

如确需重生成，申请必须说明具体镜头、数量、时长、相较上一版的实质改动、为什么现有素材难以修复、费用或费用未知、仍可能失败；明确询问是否执行这一轮。只执行本轮获批的最小范围；其他成功镜头继续复用。完成后复查前后衔接，仍不合格则重新等待用户决定。

诊断示例：动作时点偏移优先调整选段与时间线；错误文案优先用文字层替换；相邻镜头不连贯先检查首末状态和运动方向；主体外观漂移可提出加强参考或固定素材的方案，但不能自行重新调用视频生成。用户接受近似不等于技术验收完全通过，记录“用户接受差异”，不要隐瞒。

达到验收目标或遇到工具、素材、费用限制时报告现状，不以无限迭代替代限制说明。

## 8. 交付与验收

在项目中保留参考、分镜表、选定素材、时间线和对照记录；给出可访问的交付位置。交付：

1. 渲染视频：使用平台支持的输出，优先 MP4/H.264，保持参考画幅、帧率与时长，用户参数优先。
2. 用户要求时交付可编辑项目：可重新打开的 MiniMax Design 平台项目，以及平台实际保留的可编辑属性；不把生成视频当作分层可编辑动画工程。
3. 素材依赖与简短交付说明：打开方式、所需字体/插件、近似部分、未验证项及剩余限制。

播放交付视频，检查首尾、黑帧、缺帧、音画同步与时长；重新打开交付工程验证资源和可编辑性。在只有平台项目而没有可移交工程文件时明确说明，不把截图、分镜 Markdown、脚本或 MP4 作为可编辑工程。原生工程或渲染未完成时标为部分交付。

## 9. 行为验收用例

以下为技能规则测试，不代表完成真实视频联调：

1. 结果不够像，用户说“优化一下”：产出诊断和修复选项，视频提交次数为零。
2. 错字但画面可用：优先建议可执行的文字层修复；不得默认重生成视频。
3. 已有首次制作授权、预算仍有余额：验收失败仍暂停，不能把余额视作重生成许可。
4. 用户明确批准 S02 一个片段重生成一轮：只做获批范围，S01 和 S03 不动；再失败不自动提交第二轮。
5. 任务超时且可能已生成：核实产物和状态，不重复提交；需重试时再次请求授权。
6. 修复方案没有可靠报价：标明可能额外消耗积分与费用未知，不以免费名义执行。
7. 样片未通过：只诊断并等待决策，不自动重做样片或批量制作全片。
8. 用户说先保留现版：保留结果与差异记录，停止修复，不声称完全达到参考精度。
9. 用户提供原片和替换主体并要求运动复刻：默认使用平台参考生成；独立静态图生成和可编辑原工程都不是强制前置条件。
10. 用户说“所有文字换成汉堡文案”：先出完整变更脚本等待确认；不提交词库，不直接生成。
11. 原片某小字看不清：唯一定位载体并提出一个完整替换值供确认；载体仍不明确时阻塞生成。
12. 用户修改已批准文案：核对最新文档、展示差异并确认修订版，不能按旧稿生成。
13. 失败后用户确认已展示的修订脚本及本轮范围：直接执行这一轮，不追加二次授权；若再次失败仍不自动重试。用户明确只审脚本时不执行。
14. 用户要求忠实复刻但没有要求对比视频：只生成并检查主成片，不自动制作对比视频。
15. 用户要求保留原片时序：按原片事件和已核实的相对时序编译；提交前拒绝助手自行平均分段或写入未经核实的数字时间。
