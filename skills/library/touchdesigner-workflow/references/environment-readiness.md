# TouchDesigner 准备、工程归属与恢复

仅启动、连接或恢复时读取本文件；平台、路径与设备差异结合 `official-reference.md` 的“跨平台与环境探针”。安装成功、应用窗口出现、组件 Active 和端口监听分别只是准备证据，不能代替当前对话读取目标工程。

## 软件本体缺失时的用户引导

标准路径未发现 TD、进程查询不可用或连接失败，不等于确认未安装。先检查应用所在主机、已有安装记录、运行实例与已知自定义路径；仍无法定位时，询问是否安装过，必要时只请用户提供应用位置。已核验的安装直接复用，不建议重装；确认缺少软件本体后，暂停依赖它的启动和制作，不反复安装连接器。

说明需要 **TouchDesigner 桌面应用**，给出 [Derivative 官方下载页](https://derivative.ca/download) 与 [官方安装说明](https://docs.derivative.ca/Install_TouchDesigner)，用用户的语言仅展示对应系统的步骤：

| 系统 | 用户安装步骤 |
|---|---|
| Windows | 根据实际系统、硬件及连接器已说明的支持范围选择 Official 稳定版 Windows 安装器，运行并按提示安装 TouchDesigner。 |
| macOS | 选择支持实际 Mac 机型及系统的 Official 稳定版本，打开 DMG，将 TouchDesigner 拖入“应用程序”，再启动应用。 |

首次启动出现 Key Manager 时，引导用户按界面完成账号登录和适用许可的设置；只有用途符合官网条件时才介绍 Non-Commercial，不为商业项目默认选择它。登录、许可选择或购买以及系统授权由用户在官方或系统界面完成，不收集账号密码。不要以 TouchPlayer 代替用于编辑工程的 TouchDesigner，也不默认要求安装实验版或升级已有版本；兼容性未知时如实说明。

不只说“去网上搜索安装”。提供官方入口、具体步骤与下一步；官网不可访问时说明情况，不编造直链或改用第三方安装包。等待安装时保留原需求、素材、目标工程及最近验证步骤，可以继续独立参考分析，不循环启动。用户告知完成或新的检查发现应用后，重新核验实际路径、版本与许可，按下文准备或复用连接器、加载完整组件并读取目标网络；验证通过后接着原任务执行，不要求重复需求或再说“继续”。仍未发现应用时只请用户提供安装位置或具体安装错误。

## 准备连接与目标工程

1. 区分本地命令、应用控制能力与 TouchDesigner 所在主机。容器或 WSL 的系统信息不代表应用主机。发现实际安装位置、运行实例和目标文件；多个候选无法确认时先问，不猜版本、用户名、盘符或端口。
2. 已有连接能读取目标工程时直接复用。首次使用或连接缺失时，通过可用本地命令运行 `../scripts/prepare-connector.mjs`：先读帮助、检查状态，再按需安装并启用；让它继承当前 Design 对话的工作区上下文。脚本只准备客户端登记的连接器，不安装 TouchDesigner 本体，也不把应用内组件加载成功作为安装结果。下载与系统授权的等待独立于下文恢复时限。
3. 如果宿主不支持此准备入口，使用实际可用的连接器管理界面，或说明缺少的入口。结果未知先检查状态，不重复下载；已有其他可用连接时不擅自替换。系统授权由原生界面处理，不读取、复制凭证或猜测网络入口。
4. 从用户指定位置、安装结果对应资源或完整发行包定位连接组件。依赖以该包清单为准；可能包含 `.tox`、外部脚本、模块和描述文件，例如发行包声明的 `mcp_webserver_base.tox`、`modules/`、`import_modules.py`。加载后回读 `externaltox` 解析出的真实路径，并核对文件存在；相对路径需在实际工程上下文中解析。不能只复制 `.tox` 就认为资源完整。缺失时使用宿主支持的完整资源获取方式；来源未知则说明缺项，不猜下载地址或另取任意最新版。
5. 打开文件前核对进程、窗口与监听归属；同一监听位置出现多个 TD 实例时停止写入，不擅自更换端口。只对可确认属于本任务创建且没有未保存内容的多余实例正常退出，不结束其他任务的进程。应用未运行时打开已发现的 TouchDesigner。用户指定了 `.toe` 就先打开该工程；新建任务没有旧工程时，可以打开完整可信组件包的 `.tox` 完成冷启动。打开文件可能切换窗口或创建新实例；回读实际加载的工程，不能根据启动命令成功报告已就绪。
6. 应用正在运行时复用目标实例。需要保留现有工程时，在实际目标网络中导入组件，不另开组件工程；先检查是否已有同源组件，名称可以改变。连接尚未建立时不能依赖其内部脚本安装自身；使用可用且已授权的导入界面。没有安全导入能力时明确卡在这一项，不能为绕过限制另开工程。
7. 组件已经加载后不要再打开或重复导入。保留完整资源的持久路径；临时目录只用于中转，不能清理仍被外部组件、模块或脚本引用的目录。工程无需永久保存在连接组件包目录。
8. 通过当前对话读取实际工程、目标网络、组件状态和节点错误。健康状态与工程读取分开验收；某一能力失败不抹掉另一项证据。只有目标实例可区分、工程正确、实际读取成功、连接组件及父网络错误检查通过时才开始制作。无法取得错误信息属于未验证，不算通过。

## 工程归属与保存

在当前任务记录实际目标主机、系统、TD 版本与许可证、可取得的进程/窗口标识、工程目录与名称、目标网络、服务节点及父组件、实际监听归属、组件版本与完整资源路径。不可取得的标识标为未知，不自行推测。节点路径与系统文件路径分开处理。每段修改后、保存前后和断连恢复后核对这一组信息；未知的实例、工程或组件变化应停止写入。

保持原输入和用户指定的创作方式，不因断连改用其他软件。目标工程正在切换、被另一任务修改或有未保存内容时先保护现场。复制磁盘文件只保留上次保存的版本，不能声称保护了未保存修改。另存会改变工程上下文及相对资源解析；先核对授权目标和资源引用，保存单独执行，再回读路径、依赖和连接。已授权保存带来的预期名称变化在验证后更新记录，不视为意外换工程。

用户已明确授权的保存、录制与设备使用不重复询问；目标路径、覆盖范围、外部设备或录制范围不明确时，只确认相应缺项。不自动安装应用、提升权限、关闭防火墙或结束其他任务的进程。

## 有界恢复

已有连接通过上述检查可直接进入 READY；新连接按 UNKNOWN → BOOTSTRAPPING → WAITING → READY 推进。就绪后失联进入 DEGRADED → RECOVERING，恢复后重新验收才回到 READY；到时未就绪或无法安全恢复则为 FAILED。READY 表示目标工程控制已验证，不仅是下载完成。

- 冷启动等待或一次恢复各设 90 秒总时限，计入调用耗时；检查间隔 2 至 5 秒，成功立即继续。无法控制单次调用超时时，不发起超过剩余预算的新检查。该时限不是中断正常下载、授权或已知渲染的依据。
- 就绪前连接拒绝可以是启动等待；先观察真实窗口与进程，再检查同一服务组件的就绪状态，最后读取目标工程；不在应用尚未启动时连续派发工程控制。就绪后断连或服务路由缺失时先停止写入，最多做两次只读探活和工程归属检查，核对服务节点、组件版本以及 `externaltox` 的实际解析路径，不重开 `.tox`、另启实例或重放整个脚本。
- 只有确认同一工程的目标服务组件停用时才启用；初始化失败时，只尝试一次该发行包支持且可安全执行的原位恢复。组件已启用但能力缺失时，不盲目切换 Active、改源码、改端口或重新导入。
- 参数错误与应用脚本异常先检查完整返回、实际节点和参数，只修复未完成部分。结果未知时先回读，避免重复创建、连接、录制或保存。命令环境的网络隔离不能证明应用已经停止。
- 到达时限、无安全恢复方法或同一原因恢复后再次出现时保留现场，标记 FAILED 并报告已完成步骤、当前实例/工程、错误阶段和所需具体动作。连接恢复后仍须读取原目标工程，才可继续。
