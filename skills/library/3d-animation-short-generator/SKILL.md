# 3D动画短片生成器

当用户想把一句话创意做成完整的故事驱动 3D 动画短片流程，尤其是皮克斯 / 迪士尼 / Q 版 / 动态图形风格短片时使用本 Skill。所有长期产物按生产顺序整理，并在关键创意点或高成本步骤前提供结构化选项，用于批准、修订、模型选择、分辨率选择以及继续或重做。

视频生成默认使用 MiniMax-H3。若用户明确指定其他模型，先检查该模型是否支持所需时长、画幅、分辨率、参考素材、音频和运镜，再遵循用户选择。生成失败时先诊断原因，针对性修正后重试一次；仍失败则切换其他可用且兼容的模型，或改用后期合成方案，不在同一模型上反复重试。不预置或主动宣传具体替代模型。

## 第 1 步：接收输入并锁定核心简报

先确认前提、目标时长、画幅比例和音频模式，再开始做资产。3D 动画的默认音频模式是 **静音** 和 **对白主导**；只有当用户明确要做罕见的第一人称旁白推进型短片，并且接受这不是常规 3D 动画模式时，才使用 **旁白主导**。

同时锁定故事目标、希望传达的情绪、投放平台和会影响整条流程的硬约束。

## 第 2 步：写故事简报和故事大纲

先把创意整理成简洁的项目简报。

再写故事大纲，明确：
- 主角目标
- 核心冲突
- 关键节拍
- 情绪转折
- 结尾回收点

大纲要足够短，能指导生产；又要足够具体，能支撑后面的镜头决策。

## 第 3 步：生成角色卡和场景卡

创建可复用的视觉锚点：
- 主角角色卡
- 配角角色卡（如有）
- 变身前 / 变身后双角色卡
- 重要环境的场景卡

角色卡要锁定身份、轮廓、服装和变身相关细节。场景卡只写环境，不要混入人物动作。

## 第 4 步：生成镜头表

在角色卡和场景卡锁定后，再写固定镜头表。

镜头表必须写成**真正的表格**，不能写成散文。镜头表必须采用一套固定的 7 列规范，列顺序不可改、不可合并、不可省略。每一行都要按下面的内容契约填写：
- `Shot ID & Duration`：只写 `1 / 0-8s` 这种格式；先写镜头编号，再写这个镜头的总时长窗口。
- `Continuity Handoff`：先写上一镜传来的桥接状态，再用一句话写完连续性摘要。
- `Reference Anchors (Spatial + Identity)`：写这个镜头绑定的角色卡 + 场景卡。
- `Hook Type`：写一个简短功能标签，如设定钩子、揭示、追逐、反应、回收、情绪节拍。
- `Shot Description (Per-Second Directives)`：按 `0-3s`、`3-5s`、`5-8s` 这种时间切片写镜头内部动作。
- `Audio & Dialogue Track`：写最终批准的对白、说话人绑定和嘴部状态。
- `Audio Mode`：写 `silent`、`dialogue`、`mixed` 或 `SFX`。

不要把镜头表改写成叙述段落、纯项目符号笔记或混合散文；每一行都必须保持表格形态。

推荐的行写法示例（必须保持表格行结构）：
- `Shot ID & Duration`：`1 / 0-8s`
- `Continuity Handoff`：`金球不在手中；公主从花园入口走向池边并停下；青蛙声线稳定不变；C1 右侧喷泉为固定空间锚点；C2 无离场角色；C3 午后斜光从右上方打入；C4 同一下午；C5 暖绿与玫瑰粉；C6 公主视觉强度高于青蛙；C7 弱帧对齐`
- `Reference Anchors (Spatial + Identity)`：`公主角色卡 + 王宫花园场景卡`
- `Hook Type`：`设定钩子`
- `Shot Description (Per-Second Directives)`：`0-3s：... 3-5s：... 5-8s：...`
- `Audio & Dialogue Track`：`公主：... / 青蛙王子：... / Bridge beat: ... / Mouth state: ...`
- `Audio Mode`：`dialogue`


每个镜头至少包含：
- 镜头编号
- 时长
- 钩子 / 功能
- 场景与角色锚点
- 空间连续性说明
- 最终对白或动作节拍
- 音频模式
- 嘴部状态或口型说明
- 道具状态
- 来自上一镜的桥接节拍
- 声音锁 / 说话人身份说明
- 时间 / 光影 / 色彩连续性说明

镜头表规则：
- 单镜头尽量控制在 **5–15 秒**，但不要强行要求每个镜头时长相同；具体时长按剧情节拍来定
- 如果一个节拍需要超过 15 秒，必须拆成多个镜头
- 对白镜头必须坚持 **一镜一人**
- 如果同一时刻需要两个人说话，要拆成反应切镜，而不是塞进一个镜头里
- 在生成视频前先锁住连续性：持物、交接状态、站位、声音、变身形态、光影、时间和色调
- 在镜头表阶段先做时长预算：每一行都要有足够的动作、情绪或信息量，能自然支撑 5–15 秒；如果单行内容太薄、连 5 秒都撑不住，就应合并到相邻镜头或拆成前后两个镜头，而不是留到后期硬补。

## 第 5 步：写文本分镜

把每个镜头展开成一段文本分镜。文本分镜要延续同样的时长规划：每个 panel 都必须有足够的可见动作、情绪变化或对白推进来支撑预定的 5–15 秒；如果某个 panel 太薄，就应在视频前合并或重写，而不是交给后面补救。

每个镜头都要重写最终对白，并补上:
- 可见动作
- 与上一镜头连接的最小桥接动作
- 谁手里拿着什么
- 人物在画面中的起止位置
- 嘴部状态与说话人绑定
- 任何揭示、反应或变身节拍
- C1 空间锚点
- C2 离场状态
- C3 光影继承
- C4 时间线
- C5 色调
- C6 主角 vs 配角强度
- C7 弱帧对齐 vs 强帧锁死

把文本分镜写成能直接读到这些 C1–C7 字段的格式，每个镜头都必须显式出现。

单文本分镜文档的每个镜头都必须使用以下固定块格式：
- `Shot 1 — 0-8s`
- `Character / Scene binding:` 这个镜头绑定的角色卡 + 场景卡
- `Purpose:` 这个镜头的故事作用或钩子
- `Final dialogue:` 最终批准的对白，如有则写出
- `Bridge beat:` 来自上一镜头的最小可见桥接动作
- `Continuity:` 下面逐条写出 C1 到 C7，每条单独一行
- `Panel beats:` 按 0–3s / 3–5s / 5–8s 或等效的时间切分写出镜头内部动作推进
- `Mouth state:` 谁闭嘴、谁开口，以及分别在什么时候开口
- `Story function:` 这个镜头承担的叙事功能

单文本分镜文档必须对每个镜头重复这套块格式，不得把这些字段压成一段散文，也不得省略 Continuity 块。

如果故事里有变身，必须把变身前和变身后当作两个清晰的身份锚点来处理。

如果用户需要，可在这一步之后再补可视化分镜图。

## 第 6 步：自检镜头方案

检查镜头表和分镜，确认没有：
- 超过 15 秒却没有拆开的镜头
- 一个对白镜头里放了两个说话人
- 说话人身份不清或嘴部状态不一致
- 道具交接不连续
- 桥接动作缺失
- 变身连续性错误
- 时间、光影或色调漂移

有问题先修正，再进入视频生成。

## 第 7 步：逐镜生成视频

默认使用 MiniMax-H3；只有用户明确选择其他模型且能力检查通过后才切换。再按镜头逐条生成视频。

视频 prompt 要严格跟随已锁定的分镜，不要在生成阶段临时补对白。音频模式要直接影响画面处理：
- 静音：以画面、音乐和音效叙事
- 对白主导：以角色对白和口型安全为核心
- 旁白主导：罕用备选，只在用户明确要求时使用

## 第 8 步：合成成片

把已批准镜头按顺序拼接。

每个镜头都要保留完整时长，最终成片合成时不需要裁剪镜头，也不要为了缩短片长而压缩镜头，确保每个镜头的完整性。随后加入 BGM，检查是否顺滑，并确认最终成片仍然符合已锁定的故事、说话人身份、嘴部状态、道具和连续性链条。

## 第 9 步：最终复查

最终检查以下项目：
- 说话人身份是否正确
- 嘴部状态是否正确
- 道具和交接是否连续
- 变身连续性是否正确
- 时间连续性是否正确
- 音频模式是否一致

全部通过后，才交付最终 3D 动画短片。
