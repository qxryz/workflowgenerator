# 工程分析：范围、提取与结论

只读分析可以在不启动 Houdini 的情况下检查支持的工程容器；不把静态读取误认为现场 cook。先明确是整份工程还是某个网络。默认覆盖所有网络，包括多个几何容器，不只读第一个 `geo`。

## 本地提取

1. 使用 `../scripts/extract_hip.py`，指定源文件和新的临时输出目录。只支持经过校验的旧 ASCII cpio 容器；识别依赖文件头，不依赖 `.hip`、`.hiplc` 或 `.hipnc` 后缀。它拒绝不支持的编码、损坏和越界条目，不执行内嵌脚本，不覆盖已有目录。
2. 对提取目录运行 `../scripts/parse_hip.py` 输出拓扑，运行 `../scripts/extract_vex.py` 输出 VEX 与重点参数。默认检查整棵树；用户限定范围时才传子网络路径。输出是静态摘要，不是每种节点/插件的完整语义解析。
3. 格式不支持、节点无法还原或关键代码缺失时明确标记“未解析”，需要现场时通过可用 Houdini 能力读取。不能给损坏输入返回空报告并宣称分析完成。

在独立临时目录保存内部分析文件；只有用户要书面报告时才将整理结果交付到指定位置。保留输入文件和范围来源。

## 解释方法

结合拓扑与实际代码逐层解释：功能契约、实现选择、交给下游的职责、缺口和具体改进。算法名称必须由代码支持；普通属性赋值不强行套成复杂经典算法。说明属性类型、写入所有者、循环模式、反馈状态和模块依赖，区分事实、推断与待验证部分。

先读 `analysis/METHODOLOGY.md`，按问题选择 `analysis/ALGORITHMS.md`、`analysis/PATTERNS.md`、`analysis/COLLABORATION.md` 与 `analysis/DEBT_CHECKLIST.md`。原始资料里的样例统计、性能排序和“已验证”属于来源记录，不代表当前工程。不要把非 Houdini 的通用分析引导扩展为自动切换软件。
