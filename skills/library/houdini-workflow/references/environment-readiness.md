# 软件准备与目标核验

## 先分清要准备什么

连接器、Houdini 软件、许可证和可读工程是不同条件。不要把安装连接器等同于已安装 Houdini，也不要让用户在已有可执行准备途径时反复手动配置。

`../scripts/ensure_houdini.py` 使用 Python 3 标准库，默认执行准备；只读检查须带 `--status`。先读帮助，根据任务已指定的版本和实例保留选择参数。它会验证已有连接和托管注册，必要时请求客户端安装/修复，再启动匹配的软件，等待真实健康响应。返回连接就绪后仍须通过当前会话的场景控制能力读取目标工程。

脚本不负责安装 Houdini 本体或取得许可证，不复制原包里的旧桥接实现，也不需要离线安装包或历史源码目录。来源中的主要使用与连接证据来自 Windows；其他系统即使可以探测，也必须验证实际安装布局、客户端注册和场景控制，不承诺冷启动可用。

## 按实际失败阶段处理

| 状态 | 处理 |
|---|---|
| 就绪 | 核对实际控制实例与目标工程，再继续原任务 |
| 多个实例或版本不符 | 保留用户指定版本/实例；通过可用能力选择后重查，不回退到别的工程 |
| 安装进行中或响应中断 | 查状态，不重复启动安装；已有进程保留 |
| 现有实例需要重启 | 先确认未保存内容的处理方式，得到相应授权后重启；不新开空白实例绕过 |
| 软件不存在 | 使用当前操作系统的官方下载安装入口，说明本体与连接器的区别；可代为完成已授权步骤，账户登录、许可选择等需要用户本人完成的环节再说明具体动作 |
| 许可证或启动弹窗阻塞 | 说明实际问题，保留已启动进程和需求；不下载绕过许可的替代包 |
| 客户端无准备能力或缺注册 | 先区分客户端版本、托管安装失败与软件缺失；有连接器管理能力时使用它，否则说明需要的客户端更新或设置动作，不声称 Skill 能自行补齐客户端代码 |
| 工作区身份拒绝 | 刷新当前工作区上下文后再试；不改用另一工作区或无身份的入口 |

外层命令应覆盖 helper 的完整时间预算，不提前中断正常下载。超时后查真实状态；具体原因解决后再尝试一次准备。对于持续失败保留工程、启动结果和未完成步骤，报告阻碍，不要求用户重述创作需求。
