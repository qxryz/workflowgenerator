# 环境就绪与工作恢复

环境检查服务于本次 AE 制作，不进行无关全盘扫描，也不把安装技能当作已取得应用控制能力。

## 首次使用：先尝试准备，再报告缺口

保留原任务、输入文件、目标工程、未保存内容和待完成动作。简短告知用户正在准备 After Effects，然后在现有授权范围内执行。安装 skill、安装连接器、启动 AE、连接可用是不同阶段，不能相互替代。

### 1. 检查本地环境与现有能力

- 识别操作系统、AE 安装路径和正在运行的实例；多个版本时优先用户指定目标，其次复用唯一运行实例。多个运行实例或目标不明确时再问，不能默认切到最高版本。
- 有本地脚本执行能力时，使用 只读环境探测 (`../scripts/probe-environment.mjs`)，先读取其帮助。默认只扫描常见应用目录和进程；自定义路径来自宿主记录或用户提供，不进行全盘搜索。未发现标准路径不等于未安装。
- 连接器安装位置以宿主的注册记录、安装结果或真实启动配置为准。传入探测程序后可检查包是否存在、是否声明兼容启动入口；没有记录时保留“尚未定位”，不套用开发者电脑的路径。
- 分别检查本地脚本执行、连接器管理、界面操作和当前对话的 AE 控制能力。只有文件读取能力时，不能声称运行了脚本。应用进程和磁盘文件存在，都不能证明当前对话已连接。

### 软件本体缺失时的用户引导

标准路径未发现 AE、进程查询不可用或连接失败，都不能独自证明未安装。先检查已有安装记录、运行实例和已知自定义路径；仍无法定位时，只询问是否安装过及必要的应用位置。确认已安装就复用，不建议重装；确认缺少软件本体后暂停依赖它的启动和制作，不反复安装连接器。

说明需要安装 **After Effects 桌面应用**，给出 [Adobe 官方下载与安装说明](https://helpx.adobe.com/download-install/apps/download-install-apps/creative-cloud-apps/download-creative-cloud-apps.html)，并用用户的语言仅展示适用系统的步骤：

- 已有 Creative Cloud 桌面应用：打开“应用 / Apps”，找到 After Effects，选择“安装 / Install”。
- 尚无 Creative Cloud：按 [Creative Cloud 官方安装说明](https://helpx.adobe.com/download-install/apps/download-install-apps/creative-cloud-apps/download-creative-cloud-desktop-app-from-web.html) 取得安装器；Windows 运行下载的 `.exe`，macOS 打开 `.dmg` 并运行其中的安装程序，按提示完成后在“应用 / Apps”中安装 After Effects。
- 登录、购买或试用选择、组织账号权限和系统授权由用户在 Adobe 或系统界面处理；不代选付费方案，也不收集账号密码。版本应满足实际系统及连接器已说明的支持范围；无法确认时明示待核实，不默认要求升级到最新版。

不只让用户“去网上搜索”。给出官方入口、具体安装动作和安装后的下一步；链接不可访问时如实说明，不猜测直链或替换为第三方安装包。保留原需求、素材、目标工程和最近验证步骤，等待安装时可继续独立素材分析，不循环重试启动。用户告知安装完成或新的检查发现应用后，重新核验路径与版本，按下文准备或复用连接器、启动并读取真实工程；验证通过后直接续作，不要求重复需求或再说“继续”。仍未发现应用时只索取实际安装位置或具体安装错误。

### 2. 自行安装并启用连接器

1. 有本地命令执行能力时，优先使用 连接器准备脚本 (`../scripts/prepare-connector.mjs`)。先读帮助，再检查状态；缺包、未启用或未接入时执行其安装模式。脚本使用当前对话继承的宿主上下文，复用客户端的下载、安装、注册与接入流程；已安装且已接入时跳过安装。来源和版本由宿主管理，不自行复制安装器。
2. 等待真实结果，为下载和系统授权留足执行时间。结果未知或超时后先检查状态，不立即重跑安装。上下文已变化时回到当前工作区重新检查，不扫描端口、读取凭证或猜测内部地址。旧客户端缺少调用入口时说明需要支持此入口的版本；仅有本地权限不代表任何版本都可自动安装。
3. 脚本无法使用时，再尝试宿主其他真实的连接器管理能力，或已授权且可用的界面操作：进入「Skill·连接器」或同义入口，选择 After Effects，安装并确认启用。按实际标签操作，不使用记忆坐标。不再依赖新增专用的 Agent 安装工具。
4. 所有自动途径都不可用时，请用户进入连接器页面安装并启用 After Effects。只请求这一项缺失动作，保留原任务继续独立的素材分析。
5. 安装失败时记录失败阶段：下载、应用检测、桥接安装、系统授权或注册。只处理明确原因；同一失败不反复安装。系统密码和首次授权由用户在系统界面处理，不收集或写入对话、脚本、技能文件。

单独下载包只证明文件存在；必须核对注册、启用和当前对话中的控制能力。脚本报告安装与接入成功之后，仍要执行下面的应用启动和响应验证。安装 AE 连接器不包含购买或安装 After Effects 本体。

### 3. 自动启动 AE 并加载配套桥接

连接器已有有效响应时直接读取当前工程，不重载桥接。需要启动时，使用 启动辅助程序 (`../scripts/ae-host.mjs`)，通过帮助了解检查与启动用法，并使用已注册的包位置：

| 操作系统 | 配套启动器应执行的方式 |
|---|---|
| macOS | 启动或复用目标 AE，通过 DoScriptFile 执行该包的桥接启动脚本 |
| Windows | 启动或复用目标 AE，通过 AfterFX.exe -r 执行该包的桥接启动脚本；新启动的 AE 在脚本结束后继续运行，以便验证连接 |
| 其他系统 | 明确当前辅助程序不支持，不尝试套用另一系统的命令 |

辅助程序优先委托连接器包自己的启动器；没有启动声明时，可对已识别的 1.13.0 包布局执行兼容加载，当前包括 1.13.0+fix.1 分发包。它复用包中已有的桥接文件，不复制桥接代码或写入制作指令；默认不修改 AE 偏好设置，只有获得对应授权并显式启用权限修复时才改变所需开关。安装结果仅表示“没有包声明的启动器”时，仍要让辅助程序检查，不能直接断言无法自动加载。

先读取辅助程序帮助并检查兼容性，支持时执行启动。确认同一运行实例，多个实例或未知进程状态先停止。兼容加载会打开浮动面板，保持它打开；打开或复用后，向用户简短提示一次“请保持这个 AE 连接窗口打开，关闭后会中断连接”，随后继续执行，不等待确认。不强求面板停靠到「窗口」菜单对应的位置。正在渲染时不重载。

程序等待 AE 对本次加载的确认，超时会撤销本次延迟执行许可，不自动重复发送。收到加载确认后也仍须通过当前对话的连接检查和工程读取来验收；没有这两项实际结果不能开始制作。如果报错或未收到确认，先检查真实连接、系统授权或模态窗口，再处理具体原因。不支持的包需要受支持更新或该包说明的手动面板方式，不能借用另一来源的桥接。

### 4. 根据实际状态恢复，不把所有失败交给用户

使用 启动辅助程序 (`../scripts/ae-host.mjs`) 的诊断模式区分权限、应用响应与启动占用。先读帮助：本地检查不启动 AE；运行中诊断不加载面板。只有加载阶段才打开或复用应用。使用同一个已注册包和已确认应用位置，不改装其他版本。

| 检查结果 | 处理方式 |
|---|---|
| 另一任务正在启动 | 等待辅助程序在时限内复查；前一次结束后检查现有连接和工程，不能直接再加载面板 |
| 记录完整、已过期且所属进程已经结束的锁 | 由辅助程序回收并撤销旧许可，再检查连接；清理完成不能证明前一次面板加载失败 |
| 归属无法确认的旧锁、仍活跃的进程 | 保留锁并说明真实占用，不当成需要重装或手动开面板；检查原任务状态，不循环重试 |
| 当前 AE 脚本权限关闭 | 说明「Allow Scripts to Write Files and Access Network／允许脚本写入文件和访问网络」开关；已有对应修改授权时使用显式权限修复，否则只请求这一项权限变更 |
| 正在渲染、系统授权或模态窗口阻塞 | 等待工作结束，或使用可用且已授权的界面能力处理具体窗口；密码和系统授权由用户完成，不退出 AE 丢弃工作 |
| 面板已加载，连接仍无响应 | 检查当前对话的连接、目标实例和匹配面板，不将启动成功当成制作可用 |

切换语言、切换版本或重置偏好设置后重新核实权限。不同语言的偏好文件可能不同；曾经开启、某份磁盘文件为开启，都不能证明当前应用已经开启。macOS 诊断直接读取运行中 AE 并返回结果，不依赖桥接或写响应文件。Windows 命令行没有同样的同步返回通道：辅助程序无法核实时，使用当前 AE 的「Scripting & Expressions／脚本和表达式」界面；没有界面能力就准确说明这一个缺口，不声称已确认权限关闭。

辅助程序的默认启动先检查权限和渲染状态，再决定是否加载面板；显式权限修复只开启上述脚本开关，保存并回读，随后继续加载。它不关闭脚本警告、不修改系统自动化权限，也不编辑工程。技能文案本身不授予权限；已有对应授权可沿用，没有时才询问一次。处理完后由系统直接检查，不要求用户回复“已打开”。

启动时限应覆盖应用加载，外层命令时限还需按帮助留出余量。结果未知时先检查连接，再诊断；具体原因解决后最多补一次启动。二次仍失败则保留现场并报告具体原因，继续独立素材工作，不进入重启或重装循环。不同对话可以复用已就绪的连接，但制作写入仍需协调同一 AE 工程的占用。

### 5. 接回当前对话并继续制作

安装或启用后，使用宿主支持的能力刷新工具并重新检查。磁盘包存在、界面显示“已安装”或启动器返回“已加载”，都不能替代下面的验收：

- 当前对话确实可以调用 AE 控制能力。
- AE 返回真实的连接检查结果。
- 通过用户指定的连接方式读取了正确工程；首次空白工程也要有实际读取结果。

三项成立后，沿用原素材与需求继续制作，能直接检查时不让用户回复“已打开”。如果宿主需要重开对话或项目才能加载工具，先保存原任务摘要、素材路径与待执行动作，明确只卡在工具接入；不清空历史或自动重放结果未知的制作操作。

最后检查本次需要的字体、效果、渲染格式和输出目录。只查询实际依赖；知识库提到某个插件，不代表必须安装它。

## 修改期间

先确认目标合成和图层，读取真实属性及单位；不同对象的持久身份与列表序号不是同一个概念。工程切换、用户手动修改或结构变化后重新定位。增加、删除或重排属性后重新取得引用。创作操作沿用用户指定的 AE 连接方式，不能在断连时擅自改走别的执行通道。

错误明确发生在修改前时可修正原因。操作结果未知时保留现场，检查当前工程、最近结果与已保存版本，确认是否已有部分修改；不能立即重复创建、追加效果或写入动画。持续无响应时说明阻塞条件，不能循环重启。部分修改不等于全工程回滚，恢复范围必须有实际证据。

## 证据与退出条件

- 能读取正确工程与目标对象，才算可以开始编辑。
- 实际画面与属性都符合要求，才算修改成功。
- 文件可用、要求的媒体已播放检查，才算保存和渲染交付。
- 已有实际上传或挂载结果，才算返回画布。

本地恢复可能依赖用户处理首次授权或模态窗口。需要用户参与时只说明具体动作与原因，不重复询问已经明确授权的正常制作操作。
